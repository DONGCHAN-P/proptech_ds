# 평소지도

수도권 아파트 실거래를 **각 지역의 자기 평소와 견주는** 지도입니다.

```
호갱노노    비싼 곳이 빨갛다          (지역끼리 가격 비교)
리치고      오를 곳이 빨갛다          (점수·예측)
평소지도    평소와 달라진 곳이 빨갛다  (자기 과거와 비교)
```

강남과 가평은 거래량 규모가 애초에 달라서 횡단 비교가 무의미합니다. 각 지역의
지난 52주를 기준으로 지금을 재면 "뭔가 벌어지고 있다"가 제대로 잡힙니다.

이 지도가 답하는 질문은 하나입니다 — **우리 동네, 지금 평소와 다른가?**

## 실행

```powershell
.venv\Scripts\python.exe -m pulse.build_pulse   # 전처리 (약 2초, 7MB)
pulse\run.bat                                   # http://127.0.0.1:8001
```

`run.bat` 은 캐시가 없으면 전처리를 먼저 돌립니다.
`web/`(호갱노노 스타일 지도)과 포트가 달라 동시에 띄울 수 있습니다.

```
pulse/
  build_pulse.py   정본 → 평소 대비 지표 (pulse/cache/, git 제외)
  main.py          FastAPI + DuckDB
  static/          지도 프런트엔드 (Leaflet, 빌드 단계 없음)
  run.bat
```

## 화면

| 영역 | 내용 |
|---|---|
| **헤드라인** | "이번 주 시군구 82곳 가운데 57곳은 평소대로였어요" — 대부분이 평소라는 게 보통의 진실입니다 |
| **지도** | 지역: 색 = 거래량이 평소보다 많은가/적은가 · 테두리 = 값이 평소보다 빠른가 · 크기 = 표본<br>단지: 아파트 말풍선에 **마지막 실거래가 + 그 거래의 평형** · 색 = 90일 전 대비 |
| **양 끝** | 평소보다 붐빈 곳 5 + 조용한 곳 5. 한쪽만 보여주면 "거래가 늘고 있다"로 읽힙니다 |
| **상세** | 거래 건수(평소 대비) · 평단가 3개월 변화(평소 변화와 나란히) · 52주 막대그래프 · 그 안의 단지 |
| **보여주지 않는 것** | 이 지도의 한계를 접어두지 않고 같은 패널에 적습니다 |

줌 12 이상이면 읍면동, 14 이상이면 단지로 자동 전환되고, 버튼으로 고르면 그 선택을
따릅니다.

### 단지 레벨

```
[🏢 4.0억]
   26평
```

- 말풍선 숫자는 **그 평형의 마지막 실거래가**입니다. 추정가가 아니라 신고된 금액이에요
- **평형을 빼지 않습니다.** 같은 단지에서 15평과 40평이 두 배 넘게 차이 나서, 평형 없는
  가격은 어느 쪽을 보는 사람에게든 틀린 값이 됩니다. 버킷 라벨("20평대 후반") 대신
  **그 거래의 실제 전용면적**을 평으로 환산해 적습니다 — 가격과 면적이 같은 거래에서
  나온 한 쌍이 됩니다
- 평형 칩으로 고르면 마커 가격이 그 평형 기준으로 바뀝니다. 안 고르면 **대표 평형**
  (최근 1년 거래가 가장 많은 평형)이에요
- 색은 **90일 전 대비 평당가**입니다. 지역 마커(거래량)와 기준이 달라서 범례가 레벨에
  따라 바뀝니다 — 같은 빨강이 다른 뜻이면 범례를 외워야 읽히는 지도가 됩니다
- **2년 넘게 거래가 없는 단지는 지도에 올리지 않습니다.** 5년 전 거래 한 건을 "현재
  실거래가"라고 찍으면 그 자체가 틀린 정보예요
- 말풍선은 70px 쯤 돼서 도심에서는 서로를 덮습니다. 화면 좌표를 격자로 나눠 칸마다
  하나만 남기고, 지워야 한다면 **거래가 적은 쪽**을 지웁니다

단지 상세는 평형을 접지 않고 전부 펼칩니다. 그리고 **그 단지가 속한 동네가 지금
평소와 같은지**를 같이 붙입니다 — 단지만 보면 동네가 통째로 움직인 건지 이 단지만
움직인 건지 알 수 없습니다.

## 어떻게 재는가

### 거래량 — 수준으로

이번 주 거래 건수를 **그 지역의 지난 52주 평균·표준편차**와 견줍니다.
거래량은 평균회귀해서(많았던 주 다음엔 적은 주가 옵니다) 수준 비교가 뜻을 갖습니다.

### 평단가 — 속도로

**수준으로 재면 안 됩니다.** 가격은 추세가 있어서 오르는 시장에서는 이번 주 값이
지난 52주 평균보다 높은 게 당연합니다. 실제로 수준으로 재 봤더니 82곳 중 15곳이
"평소보다 높음"으로 분류됐는데, 그건 지역이 아니라 **시장 전체에 대한 정보**였습니다.

그래서 최근 13주(약 3개월) 변화율을 구하고, 그 **변화율을 그 지역의 평소 변화율**과
견줍니다. 질문이 "비싼가"에서 "평소보다 빠른가"로 바뀝니다.

### 상태 다섯 가지

| | 뜻 |
|---|---|
| 달아오름 | 거래도 값도 평소보다 빠릅니다 |
| 손바뀜 | 거래는 늘었는데 값은 평소 속도입니다 |
| **얇은 상승** | 거래는 안 늘었는데 값만 평소보다 빠릅니다 |
| 잠잠 | 거래도 값도 평소보다 조용합니다 |
| 평소대로 | 평소와 비슷한 범위 안입니다 |

`얇은 상승`을 따로 둔 이유: 몇 건 안 되는 거래로 중위가가 밀려 올라간 것일 수
있는데, 숫자만 보면 "오르는 동네"로 읽힙니다. 이름에 "얇은"을 넣은 게 그래서입니다.

라벨은 **상태 서술이지 권유가 아닙니다.** "매수 적기" 같은 말은 쓰지 않습니다
(`tests/test_pulse.py` 가 금지 표현을 막습니다).

## 사이트와 SNS 가 같은 수를 말한다

이 프로젝트는 같은 데이터로 인스타 캐러셀·스레드 글도 만듭니다. 사이트가
"평소의 1.7배"라고 하는데 같은 주 인스타 카드가 다른 수를 말하면 **둘 다
그럴듯해 보여서 아무도 못 알아챕니다.**

그래서

- 거래 원본은 **정본(`master/trade_events.parquet`)** 을 읽습니다. `web/cache` 의
  서빙용 사본이 아닙니다 — 그걸 읽었을 때 오산시가 91건으로 나왔고, 같은 주를
  인스타 카드는 98건이라고 말하고 있었습니다
- 해제(취소)·가격 이상치 필터는 `metrics.filters.trades_cte` 를 그대로 씁니다
- 기준 주, 비교 구간(52주), 신고 지연(28일)은 `metrics/build_metrics.py` 와 **같은
  상수**입니다
- 면책 문구는 API 가 승인된 고정 문구를 그대로 내려보냅니다

`tests/test_pulse.py` 가 시군구 전 건에 대해 건수와 "평소"가 한 건도 다르지 않은지
대조합니다.

> **이 작업 중에 지표 쪽 결함 두 개를 고쳤습니다** (`metrics/build_metrics.py`).
> ① 과거 구간이 주 경계에 정렬돼 있지 않아 가장 이른 주가 반쪽만 들어갔습니다.
> ② 거래가 0인 주를 `GROUP BY` 가 아예 만들지 않아 **조용한 주가 빠진 평균**이
> 나왔습니다 — 조용한 지역일수록 "평소"가 부풀려져 80곳 중 24곳이 영향을
> 받았습니다(연천군 2.81건 → 3.0건). 둘 다 "평소"를 실제보다 높게 만들어
> "평소보다 많다"를 덜 잡고 있었습니다.

## 알아둘 점

- **창이 레벨마다 다릅니다.** 시군구는 7일(SNS 콘텐츠와 같은 창), 읍면동은 28일.
  동 단위 주간 거래는 0~3건이라 7일로 보면 한 건 차이로 "평소의 3배"가 됩니다.
  화면에도 "이번 주" / "최근 4주"로 따로 적습니다
- **거래 10건 미만은 색을 칠하지 않습니다.** 캐러셀이 헤드라인에 쓰는 기준과
  같습니다 — 지도도 헤드라인입니다
- **배수가 커도 "평소대로"일 수 있습니다.** 원래 주마다 들쭉날쭉한 지역은 1.3배쯤은
  평소 범위 안입니다. 그 지역이 평소 얼마나 흔들렸는지까지 보기 때문입니다
- **σ·표준편차는 분류에만 씁니다.** 화면에는 배수와 %로만 나갑니다
  (`content/design.py` 와 같은 규칙, 테스트가 API 응답에서 `z_*` 가 빠지는지 봅니다)
- 전세·월세는 들어 있지 않습니다. 매매 신고분만입니다
- 좌표는 `web/cache/` 에서 가져옵니다. `web/build_index.py` 를 한 번은 돌려야 합니다

## 갱신

일일 배치가 `master/` 를 갱신한 뒤 전처리를 다시 돌리면 됩니다.

```powershell
.venv\Scripts\python.exe web\build_index.py      # 좌표 (단지가 늘었을 때만)
.venv\Scripts\python.exe -m pulse.build_pulse    # 지표
```

서버는 요청 시점에 파케이를 읽으므로 재기동이 필요 없습니다.

## API

| 엔드포인트 | 설명 |
|---|---|
| `GET /api/meta` | 기준일·상수·상태 범례·팔레트·면책 |
| `GET /api/regions?level=sgg\|dong&bbox=` | 지도 마커 |
| `GET /api/extremes?level=&n=` | 양 끝 + 상태 분포 |
| `GET /api/region/{level}/{code}` | 상세 + 52주 시계열 + 그 안의 단지 |
| `GET /api/apts?bbox=&q=&pyeong=` | 단지 마커 (마지막 실거래가 + 평형) |
| `GET /api/apt/{apt_id}` | 단지 상세 — 평형 전부 + 전고점 + 동네 맥락 |
| `GET /api/search?q=` | 지역·단지 검색 |
| `GET /api/health` | 캐시 상태 |

## `web/` 과의 관계

둘 다 그대로 둡니다. 같은 `master/` 를 읽고 포트가 달라 동시에 띄울 수 있습니다.

- `web/` — 호갱노노 스타일. **"얼마인가"** 를 봅니다. 평형별 시세, 전고점 대비,
  주변 인프라, 저평가·신고가 랭킹
- `pulse/` — **"평소와 다른가"** 를 봅니다. 단지 레벨에서 마지막 실거래가를 보여주지만,
  색과 순위는 끝까지 "평소 대비"입니다. 시세 추정이나 점수는 내지 않습니다
