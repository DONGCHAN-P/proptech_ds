## 2. 대본 방향

권장 중심 질문: 같은 시기에 개발된 신도시에서 왜 가격 흐름이 갈렸을까?
권장 메시지: 광교·동탄 사례에서 교통·일자리·공급의 조합을 살펴보되, 지역 전체의 거래 구성 변화와 개별 대장 단지의 성과를 구분한다.

기존 문서의 중요한 발견은 신축 입주로 거래되는 집이 바뀌면 지역 중앙가격 상승률이 실제 기존 집의 상승률과 달라진다는 것이다. 이를 숨기지 않고 영상 중간의 반전으로 활용한다.

기존 분석 문서의 동일 단지 비교값:

| 지역 | 2019→2026 | 2021→2026 |
|---|---:|---:|
| 광교 | +57% | +2% |
| 동탄1 | +78% | +2% |
| 동탄2 | +60% | -6% |
| 검단 | +33% | -13% |
| 김포 한강 | +25% | -22% |
| 파주 운정 | +24% | -23% |
| 수도권 전체 표본 | +47% | -1% |

출처: docs/longform/2026-10-10-newtown-1.md. 신규 재계산 전에는 확정 발행 수치로 사용하지 않는다. 옥정은 기존 문서가 동일 단지 표본 1~7개의 작은 표본 문제를 지적하므로 본편 비교에서 제외하거나 표본 수를 함께 보여준다.
수도권 전체라는 표현은 이 프로젝트에 수집된 지역·거래 범위를 확인한 뒤 사용한다. 공식 수도권 가격지수와 동일한 통계로 설명하지 않는다.

초기 리서치의 분양가 대비 4~5배 사례는 특정 단지와 특정 시점의 거래다. 신도시 전체 수익률로 확대하지 않는다. 분양가격·전용면적·옵션·분양 시점·최근 거래일·해제 여부를 맞춘 뒤 도입 사례로만 사용한다.
광교 +57%, 동탄2 +60%, 기준 +47%를 두고 모두 47% 올랐다고 설명하면 안 된다. 기준치와 각 지역 수치를 분리한다. 차이의 단위는 퍼센트포인트로 명시한다.
교통 1순위·일자리 2순위는 인과관계나 영향력 순위를 검증한 결과가 아니다. 여러 사례에서 관찰한 해석으로 완화한다.
동탄1·2의 거래가 있는 단지 수 차이는 공급 호수 차이와 동일하지 않다. 공급 효과를 주장하려면 입주 세대수·시점 자료로 보강한다.
광교 정의에 영통구 원천동·이의동만 들어가는지, 수지구 상현동 포함 여부와 경계를 점검한다. 동탄·검단 등도 법정동 묶음과 사업지구 경계 차이를 밝힌다.

## 4. 발행 전 검증 작업

- Python 복구 후 분석을 재실행하고 사용 데이터의 최신 계약일·수집일·해제 반영일을 기록한다.
- 2026년 부분연도와 과거 전체연도 비교의 계절성·최근 신고 지연을 확인한다. 동일 월 범위 비교를 보조표로 만든다.
- 동일 단지·30평대 분석의 실제 면적 범위, 단지 식별자, 연도별 거래 수, 비교 가능한 단지 수를 기록한다. 최소 거래 수 기준을 바꿨을 때 결론이 유지되는지 확인한다.
- 단지 상승률 중앙값은 가격지수나 반복매매 지수가 아님을 설명한다. 동일 단지라도 층·면적·거래 방식 구성은 바뀔 수 있다.
- 최초 분양가격은 모집공고 원문으로 확인한다. 3.3㎡ 단가에 평수를 곱한 추정 총액을 확정 분양가처럼 표시하지 않는다.
- GTX-A 서울역~수서 연결, 삼성역 정차, 창릉역 개통을 각각 확인한다. 2026년 3월 국가철도공단 자료는 종합시험운행 착수를 설명하며 10월 현재 실제 개통을 입증하지 않는다.
- 하남 교산 철도, 왕숙 GTX-B·9호선, 용인이동 입주 일정은 최신 공식 공고를 확보한다. 목표를 완료 사실로 표현하지 않는다.
- 개인 경험을 담은 1인칭 문장은 실제 화자의 경험일 때 유지한다. 현재 content/voice.py는 생성 음성을 타이밍용 초안으로 설명한다.
- 기존 MP4를 전편 확인해 음성·자막·차트 숫자·지도·기사 화면·출처의 일치를 검수한다.

Thinking Music by Kevin MacLeod | incompetech.com | Licensed under Creative Commons: By Attribution 4.0

assets/geo/LICENSE.md의 지도 경계 출처, assets/osm의 ODbL 메타데이터, assets/emoji/LICENSE.md와 폰트 라이선스를 대조한다.
기사 화면 PNG가 있다고 재사용 허락이 확인된 것은 아니다. 사용 기사마다 원문 URL·발행일·필요한 인용 범위·화면 출처를 기록한다. 사진·기사 전체 캡처의 사용 범위는 개별 확인한다.
AI 이미지에는 로컬 license.json과 고지를 연결한다. 실제 단지 사진처럼 보이는 생성 이미지를 실거래 사례의 증거로 사용하지 않는다.

## 6. API와 스킬 정리

| 기능 | 연결·코드 | 이번 작업 필요도 |
|---|---|---|
| 실거래 갱신 | TDATA_API_KEY, 수집 스크립트 | 최신 수치로 재집계할 때 필요 |
| 세대수·단지 기본정보 | KAPT_SERVICE_KEY, run_collect_kapt.py | 공급·세대수 보강 시 필요. HANDOFF의 과거 수집 제한은 현재 상태 재확인 |
| 좌표 | VWORLD_API_KEY / VWORLD_MAP_KEY | 기존 좌표로 충분하면 추가 불필요 |
| 학교 | NEIS_API_KEY | 학군을 본편 근거로 확장할 때만 |
| 지도 공원 | content/osm.py의 Overpass | 기존 캐시 재사용 우선 |
| 내레이션·가이드 음성 | content/voice.py의 OpenAI 연결 | 직접 녹음하면 불필요. 기존 MP3 재사용 가능 여부 확인 |
| 음성 대안 | ELEVENLABS_API_KEY | 선택 사항. 기존 제작에 무조건 추가할 필요 없음 |
| 생성 이미지 | content/aiimage.py / FAL_KEY | 추상 배경·썸네일 추가 제작 시 선택 |
| 유튜브 업로드 | YOUTUBE_CLIENT_ID/SECRET/REFRESH_TOKEN | 수동 업로드면 불필요 |
| 알림·타 플랫폼 | Telegram·Meta·Slack | 본편 사전 작업에는 불필요 |

.env.example에서 변수 이름만 확인했다. 실제 키 유효성·잔액·권한은 확인하지 않았고 비밀 값은 읽지 않았다.
현재 사용 가능한 스킬 중 imagegen은 썸네일 배경, presentations는 PPTX 수정, pdf는 분양 공고 PDF 확인, spreadsheets는 CSV 분석, documents는 DOCX 제작에 적합하다. 지금 MD 중심의 리서치 정리는 기본 파일·코드 도구로 진행할 수 있다.
skills/README.md는 Hermes 매핑 메모 수준으로 보이며, 프로젝트 전용 영상 제작 SKILL.md는 이번 목록에서 확인되지 않았다. 반복 제작이 필요하면 skill-creator로 출처 대장→데이터 검증→대본→큐시트→렌더 검수 절차를 묶을 수 있다.
Remotion과 ffmpeg는 제작 도구이지 추가 계정 API가 아니다. 현재 실행 환경에서 node는 확인됐으나 ffmpeg/ffprobe는 PATH에서 확인되지 않았다. .venv Python은 참조하던 Python 실행 파일을 찾지 못해 실행 실패했다.

## 7. 다음 실행 순서

1. 기존 MP4와 큐시트를 대조해 유지할 장면·고칠 장면을 표시한다.
2. Python·의존성·ffmpeg 환경을 복구한다.
3. 실거래 데이터 기준일을 확인하고 동일 단지 분석과 표본 민감도를 검증한다.
4. 분양 공고·철도·공급 공식 자료를 확보해 주장별 출처표를 완성한다.
5. 검증 결과를 반영해 하나의 대본으로 통합하고 큐시트·plan.json을 동기화한다.
6. 최종 녹음, 자막·크레딧·썸네일 수정 후 렌더하고 전편 시청 검수한다.

이번 점검으로 자료 지도, 기존 결과물 재사용 계획, 대본 방향, 검증 대기 항목과 API 우선순위를 정리했다. 새 수치 검증·최종 편집·업로드 완료를 뜻하지 않는다.
