# 맞춤 찾기 (질문 → Top5 → 단지 리포트) 설계

작성 2026-10-08 · 대상 `web/`

## 목적

`web/` 첫 화면을 질문 마법사로 바꾼다. 사용자 조건을 6단계로 받고, **조건 적합도**
상위 5개 단지를 지도에 하이라이트하고, 단지를 누르면 리포트 대시보드를 보여준다.
기존 지도 탐색 화면은 `/explore.html` 로 옮겨 그대로 둔다.

**"추천"이 아니라 "조건에 잘 맞는 단지"다.** 순위는 사용자가 고른 조건에 대한
적합도이고, 오를 것 같은 지표(모멘텀·가속도)는 순위에 넣지 않는다. 화면 문구는
`content/validator.py` 금지 패턴을 통과해야 한다.

## 질문 (6단계)

| # | 질문 | 값 | 비고 |
|---|---|---|---|
| 1 | 누가 사나요 | `single` / `couple` / `kids` | 3·6단계 기본값을 정한다 |
| 2 | 예산 | 매매가 상한 (만원) | 칩 + 직접 입력 |
| 3 | 평형 | 소형(10P·15P) / 59㎡대(20P) / 74㎡대(25P) / 84㎡대(30P) / 대형(35P+) 다중 | single→20P, couple→25P·30P, kids→30P·35P 기본 |
| 4 | 근무지 + 허용 통근 | 역 검색(783개) 또는 지도 클릭 · 30/45/60분 | 건너뛰기 가능 |
| 5 | 희망 지역 | 시군구 다중, "상관없음" 가능 | |
| 6 | 중요한 것 | 역세권·학군·신축·녹지·거래활발 중 1~3개 | kids 면 학군 기본 선택 |

## 순위 계산 (`web/match.py`, 순수 함수)

**후보 행** = `apt_pyeong` × `apt_index` (단지·평형 단위, 약 4.2만 행).

**하드 필터**
- `last_price ≤ 예산`, 고른 평형, 고른 시군구
- `last_date` 최근 3년 이내, `trade_total ≥ 3`, 좌표 있음
- 근무지가 있으면 추정 통근 ≤ 허용 + 10분

**점수 (0~100)** = 가격 30 + 통근 25 + 우선순위 45 (균등 분배).
근무지가 없으면 통근 25 를 가격과 우선순위에 비례 배분.

- **가격 점수** = 예산 활용 50% + 지역 내 상대가격 50%
  - 예산 활용: 가격/예산 이 0.75~1.0 이면 100, 0.4 이하면 0, 그 사이 선형
  - 지역 내 상대가격: 같은 시군구·같은 평형의 1년 평당가(`ppy_1y`, 없으면 `last_ppy`)
    백분위. 낮을수록 높다 (step5 `rel_value_pct` 와 같은 정의). **전체 모집단 기준**으로
    미리 계산해 "같은 구 같은 평형 중 하위 N%" 로 서술할 수 있게 한다
- **통근 점수**: 20분 이하 100, 허용+10분에서 0, 선형
- **우선순위**(필터 통과 후보 안에서 백분위)
  - 역세권 `walk_min` 낮을수록 · 학군 `elem_school_cnt_1km` 많을수록 ·
    신축 `build_year` 클수록 · 녹지 `green_score` 클수록 · 거래활발 평형 `trade_1y` 많을수록

**정리**: 단지마다 점수가 가장 높은 평형 1행만 남기고, 같은 법정동은 최대 2곳.
5곳 미만이면 통근 +15분 → 예산 ×1.1 순으로 넓히고 넓힌 항목을 응답에 담는다.

**이유 문구**: 기여도 상위 2~3개 항목을 사실 서술로 만든다
("역 도보 4분", "예산보다 6천 아래", "같은 구 30평대 중 평당가 하위 20%").

**부가 정보**: step7 `undervalue_top5_*` 에 (시군구, 단지명)으로 걸리면 배지.

## 통근 추정

역 데이터는 `legacy/realestate.db` `subway_stations` (역 783개, 노선·좌표).

```
도보(집→역) + 대기 4분 + 역간 직선거리×1.3 ÷ 32km/h + (노선 다르면 환승 7분) + 도보(역→회사)
도보 = 직선거리×1.25 ÷ 4.5km/h
```
집·회사 각각 가까운 역 3곳의 9개 조합 중 최솟값. 집↔회사 직선 1.5km 이내면 도보와 비교.
단지별 근접 3역은 첫 호출 때 한 번 계산해 캐시한다.

**실측 보정**: `ODSAY_API_KEY` 가 있으면 Top5 만 ODsay `searchPubTransPathT` 로 실측해
`commute.source = "odsay"` 로 바꾼다. 실패·타임아웃(3초)이면 추정값 유지.

## API

| | |
|---|---|
| `POST /api/match/count` | 부분 답변 → 하드 필터 통과 단지 수 (단계별 카운터) |
| `POST /api/match` | 전체 답변 → Top5 (점수 분해·이유·통근·배지·완화 내역) + 지도용 후보 점 최대 300개 |
| `GET /api/stations?q=` | 역 검색 |

단지 리포트는 기존 `/api/apt/{id}`, `/series`, `/trades` 를 재사용한다.

## 화면

- `index.html` = 마법사 + 결과 + 리포트, 기존 지도는 `explore.html`
- 진행바(채워지는 연결선) · 카드 좌우 슬라이드 · 답변 칩 누적(누르면 그 단계로) ·
  후보 수 롤링 카운터 · 결과 전 "좁혀지는" 연출(점이 흩어졌다 5개 남음)
- 결과: 좌 Top5 유리 카드, 우 무채색(grayscale) OSM 지도, 컬러 순위 핀 + 회사 핀,
  카드 호버 시 핀 확대 + 회사까지 점선
- 리포트: 벤토 그리드 — KPI 4칸(최근가·1년 등락·전고점 대비·출근), 적합도 항목 막대,
  시세 추이 차트, 최근 실거래, 주변 시설, 하단 면책
- Pretendard, 메시 그라디언트(단계별 색조), 라이트/다크, 모바일은 지도 위·리스트 아래

## 오류 처리

- 후보 0곳 (완화 후에도): "조건을 바꿔 보세요" + 어느 조건이 가장 많이 걸렀는지
- 역 데이터 없음: 근무지 단계 숨김
- ODsay 실패: 조용히 추정값
