서비스 방향: **내 예산으로 후보를 찾고, 가격의 변화를 비교해서 선택한다.** 기존 예산 계산 → 맞춤 찾기 → 공개 지도 → 회원 저장함에 집시계를 연결한다.

| 기능 | 연결 |
|---|---|
| 예산 계산 | 계산한 매수가 상한으로 맞춤 찾기 이동 |
| 맞춤 찾기 | 후보 카드에서 집시계 비교 진입 |
| 공개 지도·단지 상세 | 같은 단지의 과거/현재 비교 |
| 집시계 | 같은 대상의 시간 비교 / 같은 시점의 지역 비교 |
| 선택한 집의 부담 계산 | 가격을 매수가 가정으로 넣고 필요 현금·월 원리금·잔여 현금 비교 |
| 저장함 | 예산·후보·비교 결과를 당시 데이터 버전과 함께 보관 |

홈의 예산 계산 흐름을 유지하며 가격 변화로 바로 진입하는 버튼을 추가한다. PC는 듀얼 지도, 모바일은 지도 A/B 전환과 지속적인 비교 카드. 공개 공유에는 단지·시점·면적만 담고 개인 금융 입력은 계정 저장 데이터로 관리한다.

확인한 기반은 FastAPI·DuckDB·Parquet·Leaflet, 예산·회원·추천·저장 API다. 웹 캐시에 2006년 이후 수도권 거래 약485만 행이 존재했다. 기존 월별 차트는 평형별 평균이므로 새 명세의 전용면적별 중위가와 정의를 통일해야 한다. 영상용 지방 수집본은 웹 인덱스·좌표 연결을 별도 확인한다. 로컬 구현 확인이며 운영 인증·DB·공개 배포 검증 완료를 뜻하지 않는다.

개발 순서:

1. 공통 단지 ID·면적·가격 산식·기간·표본 수·산출월·스냅샷 정책 정리. 동탄·광교 생활권 경계 정의.
2. 기존 스택으로 `/timemap` 및 시간/지역 비교. 파일럿59/84㎡대, 조회기간은 보유한2006년 이후 자료 활용.
3. 후보 비교 → 가격별 월 부담 → 저장 → 공유 연결. 마지막 집계가격을 유지할 때 기준월과 실제 거래 통계를 별도 관리.
4. 비교 완료→상세→계산→저장 전환을 측정한 뒤 입지 타임라인·심층 리포트·콘텐츠 출력 확장.
