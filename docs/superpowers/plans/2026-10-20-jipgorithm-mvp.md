# 집고리즘 웹·앱 공통 기반 구현 계획

목표: 기존 FastAPI와 지도·추천 자산을 유지하며 실제 예산 계산, 회원 인증, 이용 권한, 개인 저장, 제한된 이벤트를 연결한다. 결제와 정기 리포트의 실제 판매·발송은 활성화하지 않는다.

기준 설계: `docs/superpowers/specs/2026-10-19-jipgorithm-service-direction.md`.

현재 Supabase 계정은 있으나 연결 프로젝트와 키는 미설정이다. 로컬 개발 계정은 개발 모드에서만 허용하며 공개 운영은 Supabase 인증·Postgres 설정 없이는 시작하지 못하게 한다. 사용자 변경이 있는 현재 작업 폴더에서 관련 파일만 수정한다. 기존 영상·데이터·다른 변경은 보존한다.

- [x] 순수 예산 엔진: 월 현금흐름·상환 방식·DSR 가정·LTV 가정·부대비용·비상금 제약. 0금리/부채 과다/현금 부족 테스트. 정책 자동판정이 아닌 사용자가 확인하는 가정 계산으로 명확히 표시.
- [x] 운영 저장소: 로컬 SQLite, 설정 시 Postgres. 계정/세션/저장함/요금제 권한/원자적 사용 한도/허용 이벤트/보존 삭제. 회원 간 조회·삭제 차단 테스트.
- [x] 인증: 개발 전용 로컬 계정과 Supabase REST 인증 경로. 쿠키·CSRF·원문 입력 제외·운영 설정 검사. 비회원 추천·카운트 차단과 유료 권한 차단 테스트.
- [x] 기존 추천: 예산 자동 완화 제거, 통근 출처·순위 기준 구분, 학교 명칭 정리. 기존 테스트와 strict-budget 회귀 테스트.
- [x] UI: 현재 스타일의 실제 계산 홈, 회원 대화상자, 맞춤 찾기·공개 지도 연결, 저장함·사용 한도. 입력 원문 URL 공유 제거.
- [x] 운영 준비: Supabase DB 마이그레이션·환경변수 예시·실행 문서. 카드 결제·유료 권한 부여는 비활성.
- [x] 검증: API/엔진/저장소 테스트, 실제 데이터 추천 스모크, PC·모바일 브라우저 테스트, 비밀·금융 원문 로그 유출 확인.

참고 사이트 `https://knowingasset.com/app/calculator/housebudget`에서 월 소득/지출, 상환 방식, 기간 빠른 입력, 비용 항목 분리, 결과 인쇄 UX를 확인했다. 외부 페이지의 규정·계산식을 공식 검증 없이 복사하지 않는다.
