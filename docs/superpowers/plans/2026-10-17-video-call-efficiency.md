# Video call efficiency implementation plan

**Goal:** 영상 품질·다섯 승인 게이트를 유지하면서 모델 호출과 반복 맥락을 줄인다.

**Architecture:** 제작 판단과 결정적 실행을 분리한다. 총괄은 작업 JSON 하나로 로컬 실행기를 호출하고 실행기는 로그·상태·입출력 해시를 저장한다. 입력·명령·출력이 동일하면 완료 결과를 재사용한다. 담당에게는 전체 대화 대신 짧은 task packet을 제공한다.

**Tech stack:** 기존 Python 표준 라이브러리, JSON, 기존 에이전트 TOML. 신규 서비스·패키지·모델 변경 없음.

- [x] 실제 입력 변경·출력 훼손·실패 명령·짧은 로그 반환에 대한 테스트를 먼저 작성한다.
- [x] `analysis/video_task_runner.py`에 순차 실행·해시 재사용·상태·로그를 구현한다. 자격증명/승인/게시 로직은 건드리지 않는다.
- [x] 공통 실행 정책과 task packet 템플릿을 추가하고 WORKFLOW 및 두 위치 역할 TOML에 연결한다.
- [x] 의미 있는 회귀 테스트 6개와 14개 TOML/정책 JSON 파싱을 검증했다. 영상은 재제작하지 않았다.

**Ruling:** 이번 변경은 총괄이 직접 수행한다. 구현자·검토자별 에이전트 재호출로 새 토큰 비용을 만들지 않는다.

**Limits:** 규칙 파일은 실제 앱의 컨텍스트를 자동 축소하지 않는다. 새 episode/역할은 짧은 packet을 써서 별도 작업으로 시작한다. 절감률은 다음 동일 난이도 제작에서 측정하며 현재 추정치를 확정 효과로 제시하지 않는다.
