# 영상 제작팀 운영 규칙

## 공통 제작 기준의 시작점

새 작업은 [영상 제작 마스터 가이드](guides/영상제작_마스터가이드.md)의 제작 체크리스트부터 적용한다. [요청 추적표](guides/영상제작_요청추적표.md)는 현재 대화의 요청과 로컬 역사 기록, 공통 기준과 편별 선택·대체·보류를 구분한다. 최신 사용자 지시와 해당 편 원고·음성 선택 → 마스터 가이드 → 아래 기존 상세 운영 규칙 순으로 적용한다. 현재 직접 녹음 편의 원문·말투·실제 발화 정렬을 과거 Jun·격식체·TTS 타임코드로 자동 대체하지 않는다.

저장공간은 최종 게시본·현재 기준본·현재 재현 입력·원천/재사용 자산·승인/출처/검수 기록과 대표 실패 근거를 선별 보존한다. 사용 관계를 확인한 중간 렌더·중복 사본·캐시는 사용자 정리 지시 범위에서 파일별 목록과 결과를 남기고 제거한다. 과거 폴더의 캐시라도 현재 렌더 입력이면 보존한다. 이번 정리 방법과 실행 기록은 [2026-10-27 보존 기준](../docs/video-maintenance-20261027/retention_policy.md)에 있다.

## 사용자가 여는 파일 경로

사용자용 진입점은 프로젝트 루트 `영상/<편명>/`이다. `영상.mp4`, `대본.md`, `자막.srt`처럼 짧은 이름으로 전달하고, 상태가 검토본인지 게시본인지는 해당 `파일안내.md`에 명시한다. 제작 원본과 승인·출처·검수 경로는 유지하며 `작업폴더`로 연결한다. 짧은 경로는 하드링크이므로 원본과 같은 파일이고 별도 미디어 복사본이 아니다.

새 기준본 납품 시 `config/video_shelf.json`에 정확한 버전·원본 경로·상태를 기록한 뒤 `tools/python311/python.exe -X utf8 tools/refresh_video_shelf.py`를 실행하고 원본과 같은 파일인지 확인한다. 사용자가 수정한 관리 밖 파일은 덮어쓰지 않는다. 검토본 연결을 바꾸어도 기존 승인과 게시 상태가 새 버전에 적용되는 것은 아니다. `영상` 안의 작업폴더 연결을 대상으로 재귀 정리·삭제하지 않는다. 사용자에게는 짧은 경로를 기본으로 주고 내부 버전 경로는 추적 기록에 보존한다.

영상 작업 호출은 [호출 효율 운영](guides/호출_효율_운영.md)과 `config/video_call_policy.json`을 따른다. 전체 대화 전달 대신 짧은 task packet, 로컬 작업 일괄 실행, 불변 입력 검수 재사용, 완료·장애 중심 알림을 기본으로 한다. 이 규칙은 기존 단계·승인·품질 기준을 생략하지 않는다.

모든 새 편의 화면 지시는 [채널 톤앤매너와 복기 루프](guides/채널_톤앤매너와_복기루프.md)를 공통으로 따른다. 직전 최종 영상과 광교·동탄 기준 프레임을 고정하고, 새 교통·가격·상세 장면을 같은 유형끼리 비교해 필수 차이를 수정한 뒤 본편으로 확장한다. 지정 외부 레퍼런스는 설명·근거 제시 기법을 보완하며 채널의 글꼴·배치·색·자막·지도 문법을 갈아엎는 근거가 아니다. 대표 시안의 생성 사실을 최종 스타일 통과로 해석하지 않는다.

사용자 지정 레퍼런스의 설명·자료 배치·효과음 참고는 [레퍼런스 설명·자료 연출](guides/레퍼런스_설명과_자료연출.md)을 따른다. 영상별 근거 시점과 확인 범위를 남기고, 실제 청취하지 않은 효과음을 관찰 사실로 기록하지 않는다.

새 영상 착수의 기본값은 [제작 기본가이드](guides/제작_기본가이드.md)와 `templates/episode_preflight.json`이다. 사용자 피드백의 원래 요구와 최종 채택 기준은 [사용자 피드백 이력](guides/사용자_피드백_이력.md)에 기록한다. 필요한 역할만 해당 장면·변경분을 읽고, 최종 게시본의 소스와 확정된 결정을 계승한다.

쇼츠·릴스에는 [세로영상 안전영역](guides/세로영상_안전영역.md)과 `config/vertical_video_safe_area.json`을 적용한다. 출력 종횡비만 검사하지 않고 실제 글자 경계와 앱 UI 모사를 검수한다. 과거 쇼츠의 화면 끝 제목·하단 자막 위치를 새 제작에 복사하지 않는다.

지역 상세 설명과 하단 자막 제작에는 [지역 상세 지도와 의미 단위 자막 가이드](guides/지역_상세지도와_의미단위_자막.md)를 적용한다. 사용자가 선호한 다산역 주변 배치도 방식을 기준으로 실제 주거·상업·공원 맥락을 보여주고, 자막은 숫자·단위를 포함한 의미 단위로 분할한다.

구성: 제작 총괄, 리서치·데이터, 구성·대본, 이미지·지도·썸네일, 음성·타이밍, 편집·렌더링, 독립 검수. 설정 파일은 agents/*.toml에 있다. 모델과 추론 강도는 지정하지 않아 실행 환경 설정을 유지한다.

## 실행과 등록 상태

이 패키지는 Codex 공식 custom agent TOML 형식을 사용한다. 현재 프로젝트의 .codex/agents 자동 쓰기는 권한 정책에서 거절되어 네이티브 자동 등록은 하지 못했다. 이 작업방에서는 역할 설정의 developer_instructions를 읽어 subagent 요청에 전달하면 사용 가능하다. 역할 이름으로 자동 검색·실행이 확인됐다는 뜻은 아니다.

다른 프로젝트에 네이티브 등록하려면 이 패키지의 agents/*.toml 7개를 해당 프로젝트의 .codex/agents/에 배치한다. 개인 전역 설정이 필요하면 ~/.codex/agents/에 배치한다. 기존 설정을 덮어쓰지 않는다. 실제 목록 노출/등록 여부는 새 실행 환경에서 확인한다. 설정 파일만으로 도구·계정·유료 서비스가 추가되지 않는다.

참고: https://learn.chatgpt.com/docs/agent-configuration/subagents

대본·화면 지시는 [자료화면 설계 원칙](guides/자료화면_설계_원칙.md)에 따라 문장별 자료 유형·동작·출처·확보 상태·대안을 기록한다. 사용자 유지 대상 화면은 보존한다.

## 요청별 업무 순서

| 요청 | 순서 | 생략할 작업 |
|---|---|---|
| 신규 전체 영상 | 총괄 브리프 → 리서치 → 대본 확정 → 음성 확정 → 시간표 확정 → 최종 소스·편집 → 검수 → 수정·납품 | 없음. 필요하지 않은 외부전사 생략 |
| 기존 영상 보완 | 원본/프레임 분석 → 필요한 주장/타이밍 확인 → 소스 제작 → 요청 범위 편집 → 검수 → 납품 | 대본·목소리 재제작은 요청 없으면 생략 |
| 기존 영상용 소스팩 | 화면·자막/허용된 오디오 확인 → 삽입 장면표 → 소스·짧은 클립 → 배치 가이드·검수 → ZIP 및 해제 폴더 | 전체 영상 재렌더 생략 |
| 썸네일 또는 배경만 | 총괄 요구 요약 → 시각자료 제작 → 간단 검수 → PNG 납품 | 리서치·대본·음성·전체 편집 생략 |

신규 영상에서 시각자료는 대본 안정화 후 후보·시안을 준비할 수 있다. 최종 시간표가 없는 상태에는 S001_내용.png처럼 장면ID로 저장한다. 확정 음성/원본 타이밍 이후 03m43s_S001_내용_AI.png처럼 배포본을 만든다. 시간을 바꾸어도 장면ID와 원본 에셋은 유지한다.

## 병렬 실행

총괄은 실제 도구 슬롯 한도를 확인한다. 현재 작업방은 총괄 포함 4개 슬롯이므로 전문 담당은 최대 3개를 동시에 실행한다. 7개 역할은 7개 동시 실행을 뜻하지 않는다.

- 자료 단계: research가 팩트를 확인하는 동안 visual은 사용자 구도 기반 후보만 준비할 수 있다. writer는 확인된 팩트부터 작업한다.
- 제작 단계: 대본 확정 후 narration과 visual을 병렬 실행한다. editor는 템플릿만 준비한다.
- 통합 단계: timing lock 이후 editor가 통합한다. 필요한 research/visual 수정만 병행한다.
- 검수 단계: qa는 제작 결과를 독립 확인한다. 수정은 담당자가 수행하고 qa는 변경 부분을 다시 확인한다.

## 파일 소유권과 기준

director만 state.json, scenes.json, decisions.json을 수정한다. research/facts.json, writer/script.md, visual/assets.json, narration/timing_proposals.json, editor/render와 배치가이드, qa/findings.json은 각 담당만 수정한다. 상위 담당이 편집권을 재배정할 때는 이전 담당 작업을 멈추고 재배정을 기록한다.

공통 장면표가 편집 연결의 기준이다. 필수 항목은 scene_id, 메시지, narration_text, claim_ids, 자료 유형, asset_ids, script_revision, audio_revision, start/end, timing_basis, status다. 예상 시간과 실제 시간은 구분한다. 가격은 최고/평균/중위, 단지/지역, 면적, 기간과 표본 수를 함께 전달한다.

## 서로 논의하는 체계

정례 논의는 긴 회의 대신 세 지점의 짧은 검토로 한다.

1. 대본 확정 전: research↔writer↔visual이 주장과 필요한 근거/장면을 확인한다.
2. 대표 소스·음성 후: visual↔narration↔editor가 가독성과 실제 길이, 화면 연결을 확인한다.
3. 초벌 후: qa가 장면별 필수/권장 수정을 담당자에게 전달한다.

누구든 새 증거가 있으면 수시 이슈를 열 수 있다. 메시지에는 [issue_id][scene_id] 문제 / 근거 / 권장안 / 영향 / 결정 요청을 쓴다. 관련 담당자에게 직접 보내고 총괄에도 결과를 알린다. 같은 이슈의 질의·응답 2회 뒤 미합의면 총괄이 판단한다. 단, 미확인 사실은 다수결로 확정하지 않는다.

메시지는 알림이며 decisions.json이 확정 기록이다. 총괄은 결정ID, 이슈ID, 장면, 선택, 이유/증거, 변경 담당, 종속 파일, 적용 버전을 기록한다. 실행되지 않은 역할과의 회의를 진행했다고 표현하지 않는다. 메시지 도구가 없으면 역할별 issue 파일을 총괄이 읽고 순차 전달한다.

사용자에게 넘길 사항: 원래 주제/핵심 결론 변경, 필수 원본·선호 음성 미정, 기존 권한으로 수행 불가능한 외부 전송/구매/게시. 글자 배치·보통의 전환·허용된 범위 수정은 내부 결정한다. 이미 허용된 범위의 작업을 반복 확인하지 않는다.

## 단계 통과 기준

| 단계 | 확인해야 할 것 |
|---|---|
| brief_ready | 요청 유형·결과물·원본 경로·사용자 시각 지시·권한 범위 |
| facts_ready | 핵심 주장 근거와 비교 조건. 모르는 값은 미확인으로 표시 |
| script_ready | 버전 대본·장면ID·화면 목적·발음 정보 |
| timing_locked | 실제 음성/원본 기준 start/end. 전사 불가면 화면 기준 provisional |
| media_ready | 실제 파일·자료유형·출처/프롬프트·해상도·AI 여부 |
| render_ready | 실제 렌더·입력 버전·기술 확인·검수용 증거 |
| qa_ready | 미해결 critical/required가 없음. 재생·청취 미확인 범위 기록 |
| delivered | 참조 경로·수량·ZIP 무결성 확인. 파일형식과 제작방식 설명 |

부분 작업에서는 해당 단계만 적용한다. 각 담당은 handoff.template.json 형식으로 완료 상태를 제출한다. 템플릿 자체는 완료 증거가 아니다.

## 변경과 장애

- 가격 오류: qa 이슈 → research 원자료 확인 → writer 표현 수정 → 영향받은 음성·차트·자막·썸네일만 수정 → qa 재확인.
- 음성 길이 변경: narration 새 버전/길이 → director 시간표 갱신 → editor 자막·전환 갱신, 배포 시간 파일명/가이드 갱신. 원본 에셋은 재생성하지 않는다.
- 도구 실패: 원인·진행 가능한 대안·품질 차이를 보고한다. 전사 실패는 화면 기준 임시 시간, 영상 생성 불가는 still_motion으로 명시한다. 권한 차단을 우회하지 않는다.
- 단순 재압축/해제 요청: 이미 있는 파일만 처리한다. 재생성이나 전사를 추가하지 않는다.

## 다음 제작 시작 문장

“video-agent-studio의 WORKFLOW.md와 agents/video_director.toml을 읽고 제작 총괄로 진행해줘. 주제는 [주제], 원본은 [경로], 결과물은 [전체 영상/소스팩/썸네일]이야. 필요한 전문 역할에 위임하고 decisions.json에 중간 논의를 기록해줘.”

작업 시작 때 새 episode 폴더를 만들고 templates의 JSON을 복사한다. newtown-reference는 지금까지 완료한 작업을 보여주는 예시이며, 새 영상 제작을 자동으로 시작하라는 지시가 아니다.

사용자가 작업을 중단/축소하면 총괄이 실행 중인 해당 담당을 interrupt하고 대기열을 취소한다. 부분 결과는 보존하고 이전 요청을 superseded로 기록한다. 최신 요청으로 작업 상태를 갱신하며 중단 작업은 재시작하지 않는다.

썸네일과 배경은 TH ID를 사용하며 시간 접두사는 붙이지 않는다. 단일 PNG는 ZIP 없이 제공한다. 해상도 조정 시 실제 생성 크기·업스케일 여부를 기록하고 구도와 여백을 재검수한다.
