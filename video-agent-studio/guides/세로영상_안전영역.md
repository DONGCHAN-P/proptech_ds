# 쇼츠·릴스 화면과 UI 안전영역

2026-10-16. 사용자 Facebook Reels 화면에서 발견한 상단 상태바/헤더와 하단 프로필·설명·버튼 겹침을 반영한다. **출력 해상도와 화면 안 배치는 서로 다른 설정**이다. 1080×1920으로 내보냈어도 앱 UI가 영상 위를 덮거나 화면 채움 표시에서 가장자리가 사라질 수 있다.

## 공통 기본값

### 2026-10-19 사용자 수정: 전체 화면과 글자 안전영역을 구분

창릉 쇼츠 v1은 보수적 사각형에 지도·제목·자막 전체를 작은 카드로 넣어 화면이 작고 기존 포맷과 달라졌다는 피드백을 받았다. **안전영역을 지키기 위해 영상 전체를 축소하지 않는다.** 지도·도표는 1080×1920 화면을 채우고, 읽어야 할 글자와 핵심 수치만 별도 오버레이로 보호한다. 흐린 배경만 늘리고 중앙 카드 크기를 유지하는 보완도 이 요청을 충족하지 않는다.

이번 YouTube용 수정에는 `youtube_portrait_full_frame_v2`를 명시적으로 선택한다. 큰 지도, 56px 이상 제목·54px 이상 자막·52px 이상 핵심값·26px 이상 출처를 기준으로 실제 글자 경계와 요소 간 겹침을 검사한다. 검증 명령은 `analysis/validate_vertical_layout.py <bounds.json> --profile youtube_portrait_full_frame_v2 --report <report.json>`이다.

이 프로필은 YouTube 세로 플레이어의 자체 UI 모형을 대상으로 한다. 이전의 광폭 태블릿 cover·다중 플랫폼 18개 모형을 모두 통과시키려고 다시 중앙 축소 카드로 되돌리지 않는다. 지원 범위 밖 crop의 결과와 한계는 별도로 보고한다. 기본 보수 프로필은 다른 기존 제작물 재현을 위해 유지한다. 실제 기기·앱 상태 전체를 보장하지 않는다.

단일 설정 원본은 [`config/vertical_video_safe_area.json`](../../config/vertical_video_safe_area.json)이다. 모든 신규 쇼츠·릴스는 이 설정을 읽는다. 이전 제작의 숫자를 다른 파일에 다시 하드코딩하지 않는다.

- 1080×1920, 9:16, 픽셀비율1:1, 회전메타데이터0, 기존 프로젝트30fps.
- 핵심 정보 사각형: **x156~816 / y448~1160**. 비율 기준 x14.4~75.6%, y23.3~60.4%.
- 제목, 자막, 가격, 표본수, 역·단지명, 계획/예정 표시, 비교 조건과 출처를 모두 이 안에 배치한다.
- 배경·비핵심 지도 문양은 화면 끝까지 확장할 수 있다. 중요한 위치와 값은 안전영역 안에서 큰 글씨로 다시 설명한다.
- 지도 여러 장과 조건을 한 프레임에 몰지 않고 발화 대상에 맞춰 한 장·한 대상씩 전환한다. B17을 설명하면서 별내 지도만 계속 보여주지 않는다.
- 제목/자막 최소44px, 핵심값36px, 조건/출처24px를 기준으로 실제 폰트 bbox를 측정한다. 전체 레이아웃을 통째로 축소하거나 글자만 계속 줄여 통과시키지 않는다.
- 기본 공통판에서는 장식용 브랜드 줄을 생략해 지도·자막 공간을 확보한다. 본문 흰 자막 박스는 큐 사이에도 유지한다.
- 표시할 문구가 많으면 의미 구간을 분리한다. 숫자·단위·고유명사 보호와 원문·표본 조건을 지킨다. 출처를 화면 맨 아래에 밀어놓지 않는다.

이 사각형은 **내부 보수적 제작 정책**이며 Google/Meta가 발표한 모든 일반 동영상의 공통 규격이 아니다. 플랫폼별 별도 프리셋을 추가하더라도 기본값보다 넓힐 때는 해당 화면 테스트를 다시 수행한다.

## 왜 기존 검수가 놓쳤나

기존 왕숙 템플릿은 브랜드를 y64, 자막 중심을 y1608, 조건·출처를 y1773~1890에 두었다. 이미지 안에서 글자가 잘리지 않는지만 검사했으므로 앱이 덮는 영역을 놓쳤다. 전편 쇼츠의 y1800 부근 설명도 같은 위험이 있다. 두 과거 소스는 역사적 재현용이며 새 영상의 배치 기본값으로 사용하지 않는다.

이번에는 소스 bbox·출력 MP4·화면비·앱 UI 모사를 별도로 검사한다. 지도 안 작은 글자를 보존했다는 이유만으로 가격과 조건이 읽힌다고 통과시키지 않는다.

## 필수 확인 명령과 범위

1. `tools/python311/python.exe -X utf8 analysis/test_vertical_safe_area.py`: 휴대폰7종·태블릿2종의 contain/cover **18개 기하 모형** 검사.
2. `tools/python311/python.exe -X utf8 analysis/validate_vertical_layout.py <layout_bounds.json> --report <검사결과.json>`: 실제 폰트 bbox가 최신 설정 안에 있는지 확인. 오래된 profile 또는 넘침이면 실패 처리한다.
3. 실제 출력의 대표/최장 자막·숫자·전환 프레임을 추출해 UI 모사 화면에서도 읽히는지 확인한다. 음성·자막 원문·시간은 수정 전과 대조한다.
4. 본편/자막 프레임 검사, 모형 기기 검사, 실제 앱·실제 기기 재생은 각각 다르게 보고한다. 모사 화면을 실제 iPhone·Android에서 재생한 증거라고 쓰지 않는다.

모형은 상단14%, 하단35%, 우측64CSS px UI영역을 보수적으로 가정한다. 실제 플랫폼 UI를 측정한 고정값이라고 주장하지 않는다. 초기 y360~1224안은 태블릿cover 두 경우에서 실패해 현재 영역으로 좁혔다. 테스트 로그는 `output/vertical-safe-area/`에 있다.

수동 확대, 펼친 설명·댓글, 접근성 확대, 향후 앱 UI 변경은 이 모형으로 보장하지 않는다. 4:5·3:4 피드 미리보기는 별도 점검하고, 정사각형/프로필 격자에는 별도 커버를 준비한다. **전 기기·전 앱 상태에서 절대 잘리지 않는 단일 세팅은 보장할 수 없다.**

## 공식 근거와 적용 한계

[Google의 동영상 광고 규격](https://support.google.com/google-ads/answer/13547298?hl=en)은 형식·화면에 따라 오버레이와 버튼 위치가 달라진다고 안내한다. [공식 안전영역 자료](https://services.google.com/fh/files/misc/universalsafezones-youtube.pdf)도 일부 기기에서 잘릴 수 있음을 명시한다. 이 자료는 광고용이며 일반 콘텐츠 전체에 그대로 보장되는 수치로 사용하지 않는다.

[Meta의 안전영역 안내](https://www.facebook.com/business/help/980593475366490)는 이번 조사에서 로그인 화면으로 전환돼 본문의 정확한 비율을 독립 확인하지 못했다. 인터넷의 14%/35%/6% 수치를 Meta 원문 확인값으로 기록하지 않는다. 이번 설정은 첨부된 일반 Reels 화면과 명시한 자체 모형을 함께 고려한 제작값이다.
