# 영상 제작 마스터 가이드

정리일: 2026-10-27 · 적용 대상: 부동산 데이터 채널의 기획·대본·화면·음성·검수·배포·보존

**시청자가 무엇이 왜 달라지는지 이해하고, 자기 선택에 적용할 수 있게 만든다.** 먼저 인사이트와 근거를 정리하고, 그 설명에 필요한 화면을 설계한다. 같은 차트를 띄워 수치를 읽거나 논문 내용을 차례로 소개하는 것만으로 분석을 대신하지 않는다.

이 문서는 접근 가능한 현재 대화와 아래 로컬 기록을 종합한 운영 기준이다. 접근하지 못한 과거 채팅 전체를 복원한 문서가 아니다. 요청별 근거·상태·예외는 [요청 추적표](영상제작_요청추적표.md)에 남겼다. 문서 작성만으로 기존 영상의 수정·검수·업로드가 완료되는 것은 아니다.

## 0. 적용 순서와 이번 편의 우선 기준

적용 순서는 **최신 사용자 지시 → 해당 편·버전에 유효한 승인과 원고 → 이 마스터 가이드 → 기존 상세 가이드**다. 오래된 지침과 다른 선택을 한 경우 무엇을 대체했는지 기록한다. 양립하는 규칙까지 폐기하지 않는다.

| 구분 | 적용할 기준 |
|---|---|
| 공통 | 인사이트 우선, 문장별 화면 설계, 실제 자료, 발화에 맞는 모션, 의미 단위 자막, 가독성, 실제 출력 검수, 버전·권한 기록 |
| 현재 직접 녹음 편 | 다운로드 폴더의 「현금 1억부터 5억까지」 사용자 원고와 [직접 녹음 영상 가이드](../../영상/매매가격계산/영상가이드_직접녹음_v1.md)를 입력으로 삼는다. 원고의 자연스러운 말투·순서를 우선하고 수정 제안은 분리한다. 녹음 후 실제 호흡에 맞춘다. |
| 음성 선택 | 과거 Jun은 기존 승인 음성의 계승 기준이다. 새 편의 사용자 직접 녹음이나 지정 무료 TTS를 Jun으로 자동 교체하지 않는다. 새 유료 생성에는 해당 버전의 예산 범위가 필요하다. |
| 문체 | 일반 해설은 쉽고 차분하게 쓴다. 과거 창릉 편의 합니다체 선택을 이번 사용자 작성 원고의 대화체에 강제하지 않는다. 딱딱한 논문 요약체·훈계투·반복 면책투는 피한다. |
| 자료·수치 | 2006년 이후 실거래, 미국 S&P 지표, 집값 2%·투자 6%, 현금 1~5억, LTV·금리·개인 한도는 각각 해당 편의 사양이다. 모든 영상의 기본값으로 복사하지 않는다. |
| 표지·배포 | 신도시 시리즈의 공통 표지와 매매·전세·월세 편에서 선택한 비교형 썸네일은 적용 범위가 다르다. 쇼츠 두 편·공개 전환·기존 비공개 삭제 승인도 해당 결과물에만 연결한다. |

시작할 때 [WORKFLOW](../WORKFLOW.md), 총괄 역할 설정과 [episode preflight](../templates/episode_preflight.json)를 확인한다. 템플릿의 신도시 전용 순서·옛 음성·과거 스타일 경로를 새 편에 그대로 실행하지 말고 해당 항목을 선택하거나 적용 제외 사유를 적는다. 현재 기준본은 `config/current_video.json`, `config/video_shelf.json`, 해당 episode 상태·결정 기록을 함께 확인한다. 서로 다른 편을 가리킬 수 있으므로 하나의 설정값만 보고 ‘직전 영상’을 정하지 않는다.

## 1. 기획: 인사이트를 먼저 정한다

### 1.1 한 장의 기획 메모

1. **질문:** 시청자가 지금 궁금해하는 선택은 무엇인가?
2. **발견:** 데이터나 비교로 새롭게 보여줄 차이는 무엇인가?
3. **원리:** 어떤 조건이 어떤 경로로 결과를 바꾸는가?
4. **반례·분기:** 어느 조건에서 결론이나 순서가 바뀌는가?
5. **활용:** 시청자가 자기 상황에 대입할 것은 무엇인가?

가격이 올랐다는 사실과 그 이유를 분리한다. 공급·미분양·가구 증가·청장년 이동·일자리·소득·접근성·주택 유형·시차 등 질문에 필요한 요인을 조사하고, 공통 충격에 지역별 반응이 달랐던 경로를 찾는다. 금리를 모든 차이의 답으로 고정하지 않는다. 서울·경기도 내부의 차이를 확인한다. 증거가 부족한 원인은 검증할 가설로 남긴다.

수치를 읽는 대신 변화의 구성과 제약을 보여준다. 예를 들어 자금 편에서는 ‘현금이 늘어 집값 예산이 커졌다’에서 더 나아가 자기자금·대출 증가분을 분해하고, 한도가 먼저 걸리는 구간과 월 생활비의 차이를 보여준다. 이 사례의 특정 금액은 해당 원고에서만 사용한다.

### 1.2 채널과 편 사이의 연결

실제 업로드된 전편의 결말과 예고를 확인한 뒤 다음 편의 역할을 정한다. 신도시 분석 → 주거 방식·순자산 → 감당 가능한 매매가격 → 예산 안의 지역·단지 선택처럼 사용자와 확정한 연결을 살린다. 지역별 원인 분석 등 병행 아이디어는 별도 기획으로 관리한다. 과거 논의된 순서만으로 새 업로드를 시작하지 않는다.

첫 문장과 첫 화면은 같은 구체적 질문을 제시한다. 제목·훅은 호기심을 만들되 본문이 설명하는 수준을 넘지 않는다. 결말에서 처음 질문을 회수하고 어떤 조건에서 어떤 선택이 맞는지, 다음 편에서 무엇을 계산·비교할지 연결한다.

## 2. 리서치: 데이터와 논문을 설명의 근거로 쓴다

- 핵심 주장마다 출처 URL·자료명·기관/저자·게시일·관측기간·쪽/표·집계 조건·확인 범위를 남긴다. 법·대출·세금·사업 상태는 게시 시점의 공식 자료로 갱신한다.
- 실거래는 지역·단지·전용면적·층·계약기간·취소 제외·표본수·가격 통계와 미완결 기간을 맞춘다. 지역 중위값, 동일 주택 가격 변화, 공식 지수, 투자 수익률의 의미를 구별한다. 필요한 정의는 직접 설명하고 화면에 불필요한 부정형 푸터를 반복하지 않는다.
- 월 중위값의 평균을 분기 원거래 중위값으로 바꾸지 않는다. 빈 분기·소수 표본·지역 수집 누락을 숨기거나 임의 거래를 추가하지 않는다. 중위값 변화의 거래 구성 효과도 확인한다.
- 연평균 비교는 시작·끝 날짜, CAGR/산술평균, 배당 포함 여부, 통화·환율·세금·비용을 맞춰 밝힌다. 국내 ETF와 미국 지표를 같은 시계열처럼 연결하지 않는다. 과거 실적을 미래 시뮬레이션 가정과 분리한다.
- 비용은 세금·교육세·중개보수와 부가세·등기/채권/인지·이사/수리·비상금 등의 포함 범위와 산출 근거를 설명한다. 대략 합친 가정이면 그 예산 성격을 말한다. 준비금 전부를 세금으로 이름 붙이지 않는다.
- 인과 주장은 비교 가능한 지역·시기·선행/후행·다른 요인·반례를 검토한다. 기업의 존재를 일자리 증가, 투자 발표를 실고용, 철도 계획을 단독 가격 상승 원인으로 확대하지 않는다.

### 논문을 인용할 때

논문별 소개를 대본의 기본 목차로 삼지 않는다. 먼저 설명할 원인을 정하고, 그 주장에 필요한 연구 결과만 인용한다. 말할 때는 사용자 요청에 맞춰 ‘○○○님 연구에서는’처럼 자연스럽게 소개할 수 있다. 제작 기록·설명란에는 **저자 전원, 연도, 정확한 제목, 학술지/발행기관, 권·호·쪽 또는 보고서 번호, DOI/원문 링크, 인용한 표·쪽과 결과**를 남긴다. 필요한 서지 중 확인되지 않은 것은 지어내지 않는다.

연구의 지역·기간·표본·방법과 실제로 확인한 결과를 확인한다. 저자의 결과, 우리가 데이터에서 확인한 사실, 채널의 해석을 구분한다. 특정 시기 연구를 오늘 모든 지역에 그대로 적용하지 않는다. 화면에는 해당 결과와 출처를 읽을 수 있게 제시하고 긴 서지는 설명란·근거 목록으로 연결한다.

## 3. 대본: 이해 순서와 의미 단위로 쓴다

기본 흐름은 **질문 → 필요한 용어·조건 → 근거/계산 → 왜 달라지는지 → 선택 기준**이다. 한 장면의 핵심 메시지를 한 문장으로 적고 낭독과 화면 지시를 분리한다. 용어는 처음 등장할 때 풀어 준다. 실제 금액 계산에서는 정의와 분모가 틀리지 않도록 별도로 확인한다.

문장은 쉬운 말로 짧게 이어가되 숫자·날짜·조건을 누락하지 않는다. ‘거래를 시작하는 비용’처럼 범위가 불분명하면 포함 항목과 대략 합산한 이유를 바로 설명한다. 같은 결과를 말만 바꿔 반복하지 않는다. ‘~아님’, ‘~라는 뜻은 아닙니다’로 매번 시작하지 말고 비교 기준과 사실을 직접 말한다. 불확실한 사실을 확정한 문장으로 바꾸는 것은 허용하지 않는다.

사용자가 직접 저장한 원고는 파일·버전·해시를 보존한다. 수정 제안은 원문 위치·이유·대체 문장으로 분리하고 원문에 몰래 섞지 않는다. 낭독이 바뀌면 해당 새 버전과 영향받는 자막·타이밍·화면을 연결한다. 이미 받은 승인 범위에서 필요한 수정을 진행하되 새 원고에 과거 승인을 자동 표시하지 않는다.

## 4. 문장별 화면: 자료의 기능을 먼저 설계한다

대본 단계에서 아래 행을 채운다. 장마다 같은 일반 지시를 복사한 것은 설계 완료가 아니다.

| 필드 | 기록할 내용 |
|---|---|
| 연결 | 장면 ID, 원문 문단/문장 범위, 대본 버전, claim ID |
| 메시지 | 이 말에서 시청자가 이해할 한 가지 |
| 자료 | 실제 지도·도면·공고·사진·표·그래프·모션·개념 이미지 중 주자료와 보조자료 |
| 강조 | 실제 말의 리터럴 앵커, 나타날 대상, 앞→뒤 상태, 읽을 최종 상태 |
| 근거 | 로컬 파일/URL·날짜·쪽·집계 조건·이용조건 |
| 확보 | 확보/제작 예정/좌표 검증 필요/이용허락 필요/비용 범위 확인 |
| 대안 | 같은 정보를 전달할 권리·품질이 맞는 대체 자료 |
| 시간 | 녹음 전에는 미확정, 녹음 후 실제 시작·끝과 정렬 근거 |

위치에는 지도, 규모에는 비례 도형, 시간에는 가로축, 비용에는 항목별 누적, 제약에는 상한에 닿아 멈추는 막대처럼 메시지에 맞게 고른다. 제목·글머리표·큰 문장 카드가 본문을 대신하지 않게 한다. 공고·데이터 표 자체를 금지하는 규칙은 아니다. 원자료는 읽을 행을 충분히 크게 보여준다.

### 실제 지도와 대표 건축 사례

- 지구·단지·역·사업장·시설은 이름뿐 아니라 주소·ID·좌표·기준일·운영/계획 상태로 매칭한다. 주소만 확인된 시설에 정밀 핀을 임의 배치하지 않는다.
- 거시 지도에는 권역과 주변 도시·일터·철도 관계를, 상세도에는 실제 주거·상업·공원·학교·도로 배치를 보여준다. 이름만 있는 점·사각형·동서남북 관계 상자를 상세도의 대체품으로 쓰지 않는다.
- 상세도 옆에는 **지금 설명하는 지구 전체도 한 개와 현재 범위 표시**를 둔다. 다른 지구의 전체도·노선·과거 선택 핀이 남지 않게 한다. 같은 원도면 안에서 연결하고 정합되지 않은 지도를 정확한 중첩처럼 표현하지 않는다.
- 기본은 고정 지도다. 반복 줌·빠른 팬·잠깐 전체판을 끼우는 전환을 되살리지 않는다. 말하는 면·경로·라벨·해당 레이어를 바꾸어 설명한다.
- 지도 라벨은 대상 가까이에 짧게 두고 인출선의 교차·엉뚱한 면 관통을 확인한다. 실제 시설 위치를 라벨에 맞춰 옮기지 않는다. 학교 시설번호는 필요한 경우 ‘초등학교 예정 부지’처럼 풀어 쓰되 공식 번호는 매핑 기록에 남긴다.
- 시간 설명은 가로축으로 입주·개통·개교·개점·공급·일자리의 시차를 보여준다. 목표·예정·운영·미정의 날짜 정밀도를 보존한다. 가격·현금 축을 시간축처럼 표시하지 않는다.
- 평형·공간을 설명하면 실제 단지·주택형·전용/공급면적·출처가 확인되는 대표 평면·건축 예시를 확보한다. 임의 그림의 넓이로 실제 59㎡·84㎡의 구조를 증명하지 않는다. 사용자에게 호평받은 집 단면·거실·원룸·생활 소품 중심 구도는 설명 목적에 맞게 계승한다.

## 5. 이미지·조각 영상: 다양성과 맥락을 함께 지킨다

주제가 바뀌면 그 주제를 여는 **독립 이미지 챕터**를 넣는다. 짧은 번호·주제 제목을 별도 편집 레이어에 올리고 읽을 시간을 확보한다. 사진 자체에 한글·정확한 숫자를 생성해 넣지 않는다. 필요한 이미지가 없으면 목적·구도·권리·예산을 정하고 실제 파일을 확보한다. 프롬프트만 적고 이미지 제작을 끝냈다고 하지 않는다. 기획표의 빈 슬롯을 최종 영상의 검은 화면으로 납품하지 않는다.

같은 사진이나 완성 차트를 무관한 주제에 제목만 바꿔 재사용하지 않는다. 같은 대상을 연속 설명할 때 화면과 위치를 유지하고 필요한 부분만 바꾸는 것은 허용한다. 공통 브랜드·서체·범례·의미 색을 유지하는 것과 내용 없는 반복은 구별한다. 과거 생성 이미지는 해당 의미에 맞고 구도·권리·해상도를 확인한 경우 재사용할 수 있다.

사진·생성 이미지는 생활 맥락과 분위기를, 지도·공고·데이터는 사실 근거를 맡는다. 생성 이미지를 실제 단지·공식 조감도·확정 평면처럼 사용하지 않는다. **‘AI 개념 이미지’ 배지와 내부 제작 설명은 시청자 화면에서 제거**한다. 생성 여부·프롬프트·도구·파일·출처·이용조건은 자산 기록에 남긴다.

졸라맨, 고정 자세의 그림 전체가 미끄러지는 이동, 부자연스러운 반복 보행을 배제한다. 사람이 필요 없는 설명은 공간·소품·실제 경로·관계 변화로 전달한다. 접근 경로는 작은 표식으로 도보·대기·버스·도착을 구분한다. 캐릭터를 반드시 넣어야 하는 규칙은 없다. 이모지·아이콘은 주제나 CTA에 기여할 때 짧게 사용하고 폰트 누락·깨짐·과잉 반복을 확인한다.

## 6. 차트·모션: 실제 발화에서 변화가 보이게 한다

- 한 화면의 시선 초점은 현재 설명하는 행·숫자·지역·관측점이다. 회복 분기를 말할 때 해당 점·세로 가이드·분기 라벨과 비교 고점 수준을 연결한다. 다음 발화에 맞춰 강조를 옮긴다.
- 계산 과정은 입력 → 차감/합산 → 제약 → 결과 순서로 실제로 변한다. 모든 값을 처음부터 완성한 뒤 테두리만 바꾸는 방식으로 핵심 원리의 모션을 대신하지 않는다.
- 각 금액·비율이 나오는 최초 발화에 개별 앵커를 둔다. 여러 금액의 전개를 뒤의 요약 발화 하나에 몰아 붙이지 않는다. 긴 첫 문장 동안 빈 화면이 되지 않도록 이미 말한 조건·대상을 보여준다.
- 막대 길이·누적·면적과 실제 값이 맞아야 한다. 6:4:2를 같은 길이로 그리지 않는다. 면적으로 비율을 표현하는 특수 연출은 면적비를 맞추고 가로·세로를 모두 값의 배수로 늘려 왜곡하지 않는다.
- 가격과 비율, 집값과 순자산, 원금과 원리금, 개인 한도와 정책 상한을 분리한다. 예시 가정은 적용 전에 먼저 보여준다. 미래 수익의 순서가 바뀌는 영상은 동일 규칙에서 가정만 바뀌는 모습을 보여준다.
- 한 번 움직인 뒤 충분히 읽을 상태로 유지한다. 흔들리는 spring·반짝임·장식용 반복 줌을 넣지 않는다. 지도 줌 제거를 정보가 변하는 모든 모션의 금지로 해석하지 않는다.
- **‘공식 지수 아님’ 등 반복 부정형 푸터를 넣지 않는다.** 제목·기간·단위·통계 정의·표본·조건·출처를 필요한 곳에 직접 제시한다. 필요한 불확실성은 해당 값 옆에 짧고 정확하게 남긴다.

## 7. 레이아웃과 글자 잘림: 최초 구현부터 검증한다

본문·제목·지도/차트·자막·출처의 허용 영역을 먼저 정한다. 출처는 자막 아래 별도 영역에 둔다. 큰 부제·상시 우측 장문·중앙 경고문이 자료를 밀어내지 않게 한다. 서체·굵기·색·위계는 실제 기준편에서 계승한다.

글꼴 로드 후 **실제 모든 글리프 경계와 외곽선 두께**, 변환·부모 SVG/컨테이너·clip/mask·overflow 경계를 대조한다. 기준선·좌표점이 안에 있다는 이유나 `overflow: visible`만으로 통과시키지 않는다. 가장 긴 금액·날짜·단지명, 위쪽 획·받침·축 양 끝·범례·출처를 시험한다. 겹침·어중 줄바꿈·선 교차도 검사한다.

실제 MP4의 최초 표시·강조 중·최종 상태와 긴 자막을 추출해 다시 확인한다. 과거 약 44초의 차트 상단 잘림은 해당 버전의 재현 사례다. 새 영상의 같은 시간만 검사하지 말고 공통 텍스트 컴포넌트의 영향 장면 전체를 확인한다. 요소를 계속 축소하는 대신 내용 분할·배치 조정으로 해결한다.

## 8. 직접 녹음·TTS·의미 단위 자막

### 8.1 현재 편: 사용자 직접 녹음 우선

사용자가 작성한 DOCX 원문과 자연스러운 녹음이 이번 편의 입력이다. 장별 또는 전체 파일로 받을 수 있다. WAV가 가능하면 사용하고 MP3도 처리한다. BGM·효과음을 섞지 않은 원본을 보존한다. 장비 구입을 선행 조건으로 두지 않는다. 짧은 도입부에서 전달력·방 울림·입력 크기를 먼저 확인한다. 녹음 안내의 쉬는 시간은 편집 편의를 위한 제안이며 강제 규격으로 만들지 않는다.

**원본 보존 → 실제 전사 → 원고와 다른 말·숫자 확인 → 사용할 테이크·호흡 편집 → 최종 음성 정렬 → 의미 자막 → 발화 모션·컷 → 오디오·화면 검수** 순으로 진행한다. 정해 둔 러닝타임에 맞추려고 원고나 목소리를 임의로 빠르게 늘이거나 줄이지 않는다. 기존 MP4에 소리만 갈아 끼우지 말고 장면 소스·자막·모션·컷을 재타이밍한다.

사용자 녹음에는 TTS 제공자의 문자 타임스탬프가 없다. 전사/강제 정렬·수동 확인 등 실제 사용한 근거를 기록한다. 확실하지 않은 단어와 숫자는 수동 확인 대상으로 남긴다. 원본 사용자 음성의 외부 전송은 별도 자료 범위로 확인하며, 이전에 허용한 대본·집계·화면 전송에 자동 포함하지 않는다.

### 8.2 TTS를 선택한 편

대본 확정 → 승인된 음성 생성·실제 길이/정렬 확보 → 타임록 → 본편 편집 순서다. 기존 승인 음성은 보존하고 바뀐 문장만 필요한 범위에서 생성한다. 엔진·목소리·속도·입력문·사용량·실패·재시도를 기록한다. 무료 엔진 선택과 유료 Jun 전환은 편별 결정이다. 제공자 타임스탬프를 보존하고 실제 음성과 일치하는지 확인한다. ASR의 숫자 표기 차이를 곧바로 발음 오류로 확정하거나, 신호 검사만으로 자연스러운 낭독을 통과시키지 않는다.

### 8.3 원문·읽기문·표시문을 분리한다

원문은 사용자가 확정한 내용, 읽기문은 발음용 변환, 표시문은 화면에서 읽기 쉬운 표기다. 각 변환의 원문 범위·값·사유를 기록한다. 예: `삼억 구천육백만 원`을 화면에서는 `3억9600만원`으로, `엘티브이`를 `LTV`로 표시할 수 있다. 지명 ‘삼송’ 등을 숫자로 잘못 바꾸지 않는다.

표현과 고유명사 발음은 [자연스러운 표현·발음 가이드](대본_자연스러운표현과_발음.md)와 `config/video_language.json`을 따른다. 일상적인 지하철 이용·장보기를 추상적인 기능이나 거점으로 부르지 않는다. 보호할 단지명·채널명은 일반 숫자 변환보다 먼저 처리하고, 차수·공식 식별자는 보존한다. 낭독문 수정과 실제 합성 발음의 청취 검증을 구분한다.

자막은 문장·절·완결 구절을 먼저 나누고 그 안에서 줄바꿈한다. 숫자 구성·단위·날짜·면적·역명·단지/블록 코드·조건을 보호한다. `8만 / 114세대`처럼 수를 쪼개지 않는다. 보통 1~2줄이며 길면 앞뒤 의미 단위를 조정한다. 연결 대조는 명시적 표시 변환표를 적용한 후 수행해 누락·중복·순서 변경·값 변형을 찾는다.

자막의 의미 분할과 음성 싱크는 별도 검사다. 문자 수 비율로 나눈 시간은 추정으로 적는다. 실제 음성이 확정되기 전 초 단위 타이밍을 확정한 것처럼 쓰지 않는다.

### 8.4 자막 박스·브랜드·마무리

본문의 흰 자막 박스는 짧은 큐 공백에도 위치·크기·밝기를 유지하고 글자만 바꾼다. **무발화 브랜드 인트로·아웃트로와 마지막 무음 CTA 유지 구간**에서는 박스를 숨긴다. 브랜드 뒤 첫 본문 자막이 사라지거나 앞 장면이 되살아나지 않게 경계를 확인한다.

기존 승인 클린 브랜드 자산과 BGM을 계승한다. ‘기존 채널 브랜딩용’ 같은 내부 문구가 남은 버전을 복사하지 않는다. 기본 자산의 5초 인트로·10초 아웃트로는 실제 파일과 해당 편 구성을 대조한다. BGM 진입/종료 페이드·발화 덕킹·라이선스와 크레딧을 유지한다.

마지막 **실제 발화 종료 후 3초**에 아웃트로를 시작한다. 원본 음성의 꼬리 무음도 그 3초에 포함하며 이미 들어간 여백을 중복 가산하지 않는다. 종료 기준이 청취인지 제공자 정렬인지 기록한다. CTA 아이콘은 짧게 진입한 뒤 안정적으로 유지한다.

## 9. 전체 제작 전에 대표 세 유형을 통과시킨다

1. 해당 편의 실제 기준 영상·대본·음성·브랜드·스타일 입력을 경로와 해시로 고정한다. 현재 직접 녹음 편은 공개된 매매·전세·월세 편과 같은 기능의 화면을 비교 대상으로 삼는다. 왕숙·광교/동탄의 지도 문법은 지역 장면에 맞게 참고한다.
2. 같은 메시지 유형의 실제 인코딩 프레임을 나란히 놓고 글꼴/굵기·색·본문/자막/출처 위치·정보량·자료의 역할·강조·읽을 시간을 비교한다. 다른 편의 수치나 노선을 복사하지 않는다.
3. 가장 어려운 세 유형을 실제 크기와 축소 화면에서 내부 검수한다. 이번 직접 녹음 가이드의 제안은 **현금→집값 계산 / 한도에 멈추는 대출 / 비용 영수증**이다. 지역 편은 **교통+달력 / 가격 근거 / 생활 상세도**처럼 고른다.
4. 필수 차이를 수정한 컴포넌트만 전체로 확장한다. 대표 시안 생성이나 세 장 통과를 본편 전체 완료로 보고하지 않는다. 통상적인 디자인 선택마다 사용자 확인을 새로 만들지 않는다.

외부 레퍼런스는 질문→근거→생활 의미→조건부 판단, 현재 대상 강조, 자료 기능 교체를 배운다. 채널의 글꼴·자막·팔레트·브랜드를 갈아엎는 근거로 쓰지 않는다. 원영상의 프레임·음원 재사용 허가는 별도다. 실제 듣지 않은 효과음을 관찰했다고 쓰지 않는다.

## 10. 최종 검수: 실제 파일·실제 범위로 기록한다

| 검수 | 확인할 내용과 증거 |
|---|---|
| 내용·계산 | 주장·비교 조건·산술·대출/세금 정의·원문/낭독/표시값·도형 비례·출처 |
| 프레임 | 모든 장면의 첫 상태·중간·최종 상태, 긴 자막·주요 숫자·출처·관측점·이전 강조 초기화 |
| 컷 | 의도한 컷 목록과 실제 출력 대조. 모든 경계 직전·첫·다음 프레임에서 플래시·옛 지도·빈 화면·자막 누락·브랜드 복귀 검사 |
| 모션 | 연속 프레임 또는 재생으로 이동·정지·계산 전개·발화 앵커를 확인. 스틸 한 장만으로 속도·자연스러움을 판정하지 않음 |
| 음성·BGM | 실제 청취로 숫자·고유명사 발음·말의 자연스러움·호흡·자막 싱크·음악 가림·구간 음량·브랜드 접합 확인 |
| 기술 | 전체 디코드·프레임레이트/PTS·해상도·오디오 길이·클리핑·오류·파일 해시. 도구 종료 코드와 오류 로그도 보존 |
| 시청자 관점 | 질문이 해결되는가, 반복 설명/화면은 없는가, 휴대폰에서 읽히는가, 원인과 근거·가정이 구분되는가 |

실제 청취, 연속 재생, 표본 프레임 확인, 소스 경계 검사, ASR, 신호 검사는 각각 **수행 여부·구간·수량·미확인**을 적는다. 디코드 성공을 시각·음성·미감 전체 합격으로 바꾸지 않는다. 미실시 항목이 있는 검토본은 그 상태를 분명히 전달한다. ‘완벽’ 대신 해결된 필수 수정과 확인 범위를 제시한다.

### Claude 협업과 독립 QA

사용자가 요청한 Claude Opus/max 협업은 실제 이용 가능한 승인 계정·도구로 실행한 경우에만 수행했다고 기록한다. 초안 → 논의/필수 수정 → 새 버전 → 재검수의 결론과 입력 해시를 남긴다. 제작자 자체 점검과 독립 검수의 역할을 구분한다.

최종 검수에는 허용된 대본·자막·공개 집계·조건·검수 기록·실제 화면 묶음을 정확한 버전으로 전달한다. 자료 범위·외부 서비스·유료 API 여부를 기존 승인과 대조한다. 개인 거래·음성·계정·키를 기존 화면 패킷 승인에 끼워 넣지 않는다. 대체 유료 API로 조용히 전환하지 않는다.

필수 수정은 담당 수정 → 영향 범위 재검수 → 해결 증거로 닫는다. Claude와 제작팀 양쪽의 필수 수정이 남지 않아야 최종본 단계로 올린다. 표본 이미지 검수의 승인을 실제 청취·연속 시청 승인으로 확대하지 않는다. 동일 경로라도 파일이 바뀌면 새 해시와 영향 검수로 연결한다.

## 11. 썸네일·쇼츠·업로드

### 썸네일과 제목

본문이 답하는 선택 문제를 짧게 제시한다. 비교 대상과 궁금증을 한눈에 보이게 하며 수익 보장·근거 없는 순위로 유입을 만들지 않는다. 신도시 시리즈는 사용자 확정 공통 틀의 큰 지역명·지구명·짧은 질문과 템플릿을 계승한다. 매매·전세·월세 편은 A형 제목과 세 주거 방식 비교형 이미지 선택을 해당 편의 결정으로 유지한다. ‘??’ 차트형은 함께 만든 대안이며 최종 선택과 구분한다. 다른 주제의 표지를 무조건 세 칸 비교로 만들지 않는다.

### 쇼츠

본편 검수 후 한 문제·한 근거·한 결론이 끝나는 단독 가치 구간을 고른다. 유입용과 분석 요약용처럼 목적을 구분할 수 있다. 두 편은 매매·전세·월세 편의 요청이며 모든 편의 영구 개수로 고정하지 않는다.

모든 음성 편집점과 마지막 5~10초를 별도 검수한다. 제공자 문자 타임스탬프만으로 문장 끝을 자르지 말고 원음의 앞뒤 구간·파형·전사를 대조해 마지막 발음과 다음 문장의 첫소리를 구분한다. 다음 문장의 첫소리가 들어왔다가 잘리는 현상을 제거하고, 완결된 발화 뒤 마무리 화면을 읽을 시간을 남긴다. 최종 MP4에서도 같은 경계를 확인하며 파형·ASR 검사를 실제 청취로 기록하지 않는다.

세로 화면은 9:16으로 **새로 배치**한다. 본편 중앙 크롭·전체 축소 카드·흐린 배경 확장만으로 끝내지 않는다. 지도·도표는 화면을 채우고 제목·핵심값·자막·조건·출처를 앱 UI에서 보호한다. 최신 `config/vertical_video_safe_area.json`의 대상 프로필을 명시적으로 선택한다. YouTube용 `youtube_portrait_full_frame_v2`와 기존 다중 플랫폼 보수 프로필의 좌표·글자 크기를 섞지 않는다. 실제 글자 경계·UI 모사·가장 긴 큐를 검사한다. 모사 검사를 실제 모든 기기에서 재생한 것으로 보고하지 않는다.

### 업로드와 상태

제목·설명·출처·챕터·썸네일·자막·음악 크레딧·본편 연결을 준비한다. 관련영상 설정 등 실제 가능한 기능과 미적용 기능을 구분한다. 업로드 대상 파일 해시·영상 ID·요청 공개 상태·처리 결과·실제 메타데이터를 조회해 기록한다. 비공개 업로드·공개 전환·기존본 삭제는 각각 승인된 대상을 대조한다. 새 파일 생성이 이미 게시된 영상을 바꾸는 것은 아니다. 조회수나 추천 노출을 보장하지 않는다.

## 12. 비용·권한·소통

`topic / script / budget / completed / pre_upload`의 결정 근거를 해당 편·버전·파일·자료 범위·공개 상태에 연결한다. 이번 사용자 요청과 이미 받은 유효한 승인을 먼저 확인하고 같은 내용을 되묻지 않는다. 일반 배치·편집·리서치 분담은 제작팀이 처리한다. 범위가 실제로 바뀌거나 권한·비용이 부족할 때 필요한 결정만 요청한다.

유료 생성 전 예상 입력·사용량·크레딧 상한·현재 잔액·추가 결제·충전·초과 사용·재시도 조건을 정한다. 과거 본편 Jun 10,739크레딧 같은 상한을 다른 편에 이월하지 않는다. 도구 설치·계정 로그인·예산 확인·검수 승인 자체가 새 생성·외부 전송·게시의 무제한 허용은 아니다.

텔레그램은 명시된 본인 채팅·브리지 범위에서 단계 결과·차단·결정 필요 사항을 전달한다. 특정 보고서를 로컬로만 보겠다는 답변을 모든 미래 연락의 철회로 확대하지 않는다. 큐 접수/실행/완료/발송 성공을 구분하고 PC·인터넷·도구가 꺼져도 영구 무인 실행한다고 약속하지 않는다. 메시지 본문을 셸 명령으로 실행하지 않는다.

## 13. 재작업·호출·용량 관리

### 변경에 비례해서 작업한다

최신 요구·입력 경로/SHA·승인·수정 장면·소유 파일·수용 기준만 task packet에 담는다. 필요한 역할만 실제 슬롯 안에서 호출하고 실행·등록·계획을 구분한다. 원문 대화 감사가 필요한 이번 같은 경우를 제외하면 모든 담당에게 전체 대화를 복제하지 않는다.

공통 결함은 텍스트/자막/시간축 컴포넌트의 최악 조건에서 먼저 고친다. 작은 도구 실증 → 대표 장면 → 부분 렌더 → 통합 순서로 진행한다. 바뀐 문장·장면과 영향을 받는 자막·음성·타이밍·이미지만 다시 만든다. 불변 원자료·정렬·자산·검수는 입력·코드·출력·의존 버전이 같을 때 재사용한다. 음성이 바뀌면 실제 시간표와 관련 컷은 재검수한다.

### 보존과 삭제를 함께 설계한다

| 선별 보존 | 사용 관계 확인 후 삭제 가능 |
|---|---|
| 실제 최종 게시본·현재 사용자 검토 기준본·해당 자막/메타데이터 | 더 이상 참조되지 않는 중간 인코딩·부분 렌더·실패 출력 |
| 원고 원본·원천 데이터·사용자 원본 녹음·승인 음성·현재 재현 입력 | 재생성 가능한 프레임 대량 추출·임시 이미지/오디오 변환·캐시 |
| 현재 재현 코드·의존 자산·버전/환경 manifest·필요 계산 | 보존 원본과 동일함이 확인된 패키지·복제본·중복 배포물 |

모든 폐기 시안을 영구 보존하지 않는다. 반대로 ‘예전 폴더’라는 이유만으로 최종본·현재 의존성·원천을 삭제하지 않는다. 사용자 정리 지시가 있으면 **가이드/피드백 정리 → 실제 파일 사용 관계 → 보호·삭제 목록 → 절대 경로·재귀 범위 확인 → 삭제 → 성공/실패·실제 해제 용량 기록** 순으로 실행한다. 사용자 진입 폴더의 작업폴더 링크나 junction을 따라 재귀 삭제하지 않는다. 하드링크는 이름을 지워도 다른 링크가 남으면 물리 용량이 해제되지 않을 수 있어 논리 크기와 구분한다. 원본 대화·자격증명·다른 업무 데이터는 범위 밖이다.

최종 납품은 `영상/<편명>/`의 짧은 진입 경로와 검토본/게시본 상태로 전달하고 내부 버전·원본 연결을 유지한다. 하드링크 별칭은 원본과 같은 파일이므로 직접 덮어쓰지 않는다. 새 버전 고정 후 shelf 연결을 갱신한다. 정리 담당과 문서 담당의 소유 파일을 분리한다.
