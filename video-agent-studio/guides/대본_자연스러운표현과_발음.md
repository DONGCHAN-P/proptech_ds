# 대본의 자연스러운 표현과 발음

2026-11-04 사용자 피드백을 적용한다. 설정 원본은 [`config/video_language.json`](../../config/video_language.json)이다. 대본을 작성할 때와 TTS 읽기문을 만들 때 모두 확인한다.

## 시청자가 실제로 쓰는 말

일상에서 무엇을 하는지 구체적으로 말한다. “집과 업무·장보기 기능을 지도에 놓는다”는 표현은 “집과 일터, 장 볼 곳이 어디에 있는지 지도에서 살펴본다”로 풀어 쓸 수 있다. 확인하지 않은 마트·시장·이동시간을 새 사실처럼 보태지 않는다.

| 문맥 | 자연스러운 후보 |
|---|---|
| 지하철 출퇴근을 설명하는 철도역·철도 이용 | 지하철역, 역, 이용할 지하철 노선 |
| 철도와 버스가 만나는 생활 거점 | 지하철과 버스를 갈아타는 곳 |
| 장보기 기능·장보기 목적지 | 장 볼 곳, 마트나 시장, 장을 보러 가는 길 |
| 업무 기능 | 일터, 업무시설 |
| 주거권·권역을 골라보는 방식 | 살 동네를 비교하기, 우리 생활에 맞는 동네 찾기 |
| 지도를 읽습니다·연결해 보는 방식입니다의 반복 | 무엇이 어디에 있는지 살펴보기, 집에서 어디로 어떻게 가는지 비교하기 |

용어를 금지 목록처럼 일괄 치환하지 않는다. 공식 철도 사업명·KTX·SRT·일반열차를 지하철로 바꾸지 않는다. GTX를 설명할 때는 GTX·노선명을 정확히 말한다. 대중교통의 실제 종류와 확인된 연결 관계를 지킨다.

## 단지명과 고유명사

데이터 식별자·공식 단지명, 화면 표시문, 발음용 읽기문을 분리한다. 공식 명칭의 `2차` 같은 구분을 빼지 않는다.

고유명사 사전을 일반 숫자 읽기 변환보다 먼저 적용한다. 이번 편의 기존 읽기문은 `상계2차중앙하이츠`를 `상계이 차중앙하이츠`로 바꾸고 있었다. 새 읽기문에는 아래 발음을 명시하고, 기존 잘못된 읽기문을 그대로 복사하지 않는다.

TTS 입력 준비에는 `video-agent-studio/lib/narration_reading.py`의 `apply_name_readings`를 사용할 수 있다. 이 함수는 읽기문 사본의 보호 명사만 변환하고, 금액·연도·철도 종류 같은 일반 내용은 바꾸지 않는다. 그 뒤 일반 숫자 변환을 수행한다. 회귀 사례는 `tests/test_narration_reading.py`에 보존한다.

- 데이터 이름: `상계2차중앙하이츠`
- 화면 표시 후보: `상계2차 중앙하이츠`
- 읽기문: `상계 이차 중앙 하이츠`

단지명 전체를 붙여 음성에 보내지 않는다. 지나치게 많은 쉼표나 음절별 마침표로 끊는 방식도 피한다. 먼저 단어 사이를 띄우고 실제 짧은 음성에서 억양·이름의 구분·다음 단어로 이어지는 호흡을 확인한다. 띄어쓰기 수정이나 ASR의 표기 일치만으로 발음이 자연스러워졌다고 판정하지 않는다.

## 인트로와 근거

채널의 목적 → 어떤 데이터를 왜 선택했는지 → 이번 편이 보여줄 범위 순서로 연결한다. 이번 신혼부부 편은 지역 선정의 출발점을 신혼부부 거주 통계에서 찾았다는 점을 분명히 말한다. 거주 수 순위를 가격·매수 수·선호도나 구매 가능성 순위로 바꾸지 않는다. 데이터가 답하지 않는 내용을 덧붙이지 않는다.

## 작업 순서

표시문과 읽기문을 문장 ID로 묶고 변경 전후·이유·유지할 사실을 남긴다. 반복되는 추상어와 고유명사를 검수한 뒤 바뀐 문장만 음성 생성 대상으로 추린다. 기존 음성과 대본의 해시를 보존하고, 새 원고·예산·실제 새 음성·타이밍을 구분한다. 새 발음으로 생성한 문장은 자막과 관련 컷도 실제 발화 시각으로 다시 맞춘다.
