# 공식 SHP 좌표 연결 독립 검토

**공식 원문과 8,288개 연결 후보의 조인·원투영 대표점 검증은 통과했다. 위경도 변환의 독립 PROJ 비교와 최종 지도 검수는 통과하지 않았다.** EPSG:5179를 직접 사용하는 편집 경로를 권고한다.

## 실제 검증

- 사용자 제공 공식 ZIP SHA `44cd4bd9df1c2582d0e022bd5f630df6709b37cd98ae72ff3cc48676e7dbd2e8` 일치, ZIP CRC 통과, 추출 파일과 ZIP 내부 각 파일의 byte 일치를 확인했다. 원본·타담당 파일은 수정하지 않았다.
- DBF **45,851개** 레코드를 별도 파싱해 전체 속성과 record_index·삭제 플래그가 `official_attributes.parquet`와 정확히 같음을 확인했다.
- SHP Polygon **45,851개** 레코드를 별도 파싱해 DBF 레코드 수와 맞췄다. 수도권 **20,058개** geometry의 공식 ID·PNU·원문 속성과 source_record_index를 원문에 대조했다.
- 수도권 20,058개 x_5179/y_5179 대표점은 모두 원본 폴리곤 내부다. 다중 ring의 홀을 포함한 parity 검사를 사용했다. 이는 단지 도형 내부점이며 출입구·동·세대·보행 접근점 검증은 아니다.
- 전체 실거래 catalog **9,172개**와 reviewed links 식별자 집합이 같다. map_eligible **8,288개**는 각 공식 레코드의 PNU 법정동+본부번, 원문에 산표기가 있는 경우 산 구분, 정규화 정확 이름이 **같은 실거래 입력행**에서 함께 일치한다. 필지는 한 행에서, 이름은 다른 행에서 얻는 조합 오인도 없는지 별도로 확인했다.
- packet 8,288개와 reviewed links의 공식ID·PNU·원문 레코드 번호·좌표값은 전량 일치한다. 후보 안에서 공식ID 중복은 없다.

| 구분 | 단지 수 | 처리 |
|---|---:|---|
| 필지·정확 정규화 이름 일치, 공유 공식ID 없음 | 8,288 | 원투영 대표점 draw 후보 |
| 여러 RTMS ID가 같은 공식ID 사용 | 44 | 제외 |
| 유일 필지지만 이름 불일치 | 37 | 제외 |
| 복수 공식 후보 | 21 | 제외 |
| 미매칭 | 782 | 제외 |
| 합계 | 9,172 | 후보 8,288 / 제외 884 |

공유 공식ID에 연결된 44개는 모두 eligible=false다. 이를 하나의 가격 단지로 임의 합치지 않았고, 지도에 같은 공식 단지를 여러 번 찍지도 않는다. 미매칭은 고가 단지라는 의미가 아니다.

## CRS와 권장 사용 경로

실제 PRJ는 GRS80/Korea 2000, Transverse Mercator, 중앙경선127.5°, 원점38°, 축척0.9996, false E1,000,000/N2,000,000m로 EPSG:5179의 파라미터다. 원문의 미터 좌표에서 대표점의 내부 여부를 검증했으므로 이 경로에는 위경도 역변환이 필요 없다.

권장 계약은 다음과 같다.

1. `coordinate_links_reviewed.parquet`의 eligible만 사용한다.
2. `HSMP_INNB`로 `capital_official_geometry.parquet`를 one-to-one 조인한다.
3. `x_5179`, `y_5179`를 배경도와 동일 EPSG:5179 축의 선형 viewport로 직접 표시한다. 화면 y는 북쪽이 위로 가도록 뒤집는다.
4. 배경 경계의 실제 CRS와 같은 축인지 확인하고, 단지점/범례/숫자 모두 이 경로에서 생성됐다는 새 입력 receipt를 남긴다. 기존 longitude/latitude로 다시 forward 변환하는 코드를 조용히 재사용하면 직접 좌표 경로가 아니다.

현재 `coordinates_verified_source_packet.json`에는 lon/lat만 있으므로 **그 파일이 이미 직접 EPSG:5179 입력 계약인 것은 아니다.** `native_coordinate_audit.json`은 QA 소유의 8,288개 원투영 대조 기록으로 제공했다. 편집 담당이 자기 소스에서 명시적으로 계약을 바꾸고 actual frame을 검수해야 한다.

Python311 환경의 pyproj·GDAL/osgeo·shapely·pyshp와 PATH의 proj/cs2cs/gdaltransform을 확인했으나 사용할 수 없었다. 기존 workspace .venv/tools 검색에서도 PROJ 실행 도구를 찾지 못했다. 새 설치나 API 요청은 하지 않았다. 별도 PROJ와의 위경도 변환 대조는 **미실시**다. 기존 정·역변환 왕복 오차를 독립 PROJ 검증으로 바꾸어 기록하지 않는다. 이 한계를 우회하려면 위의 원투영 직접 사용 경로로 진행한다.

## 권리·시점과 남은 검수

공식 제공 원문과 저장된 다운로드 검토 기록에는 한국부동산원 PUBLIC·무료 및 공공저작물 자유이용 안내가 있고, ZIP 내부 추가 이용조건 문서는 없다. 기존 인계의 출처 조건을 유지한다: **한국부동산원 공동주택 단지 연계정보(2025) · 좌표 가공**. 이번 검토는 새로운 외부 페이지 재조회나 권리 부여가 아니다. 경계 자료의 출처·권리는 별도로 보존한다.

2025판의 공간 시차, 2026 행정구역 코드 변경, 제외 884개 문제는 남는다. 이들은 후보를 보수적으로 제외하는 조건으로 기록해야 하며 ‘수도권 전체 단지 좌표 완료’로 표현하면 안 된다. source 시점 차이를 가격 오류나 고가 여부로 해석하지 않는다.

최종 지도는 아직 보류다. 8,288개 집합으로 다시 집계한 연도별 관측/이하/초과/미거래와 실제 draw/라벨 분모, 배경 정합, 세로 안전영역, 정확10억·재등장·첫관측전의 인코딩 상태를 다음에 확인한다. 기존 6초 시안은 새 좌표·새 가격 packet의 검수 증거가 아니다.

증거: `official_coordinate_independent_review.json`, `native_coordinate_audit.json`, `verify_official_coordinates.py`. 새 API·유료 생성·미디어 변경·외부 전송 0건.
