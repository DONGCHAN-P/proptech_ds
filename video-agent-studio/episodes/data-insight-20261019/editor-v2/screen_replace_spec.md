# v2 실제 기기 화면 합성 준비

완성 샷은 사람·모니터/폰 베젤·손/키보드·시선을 포함한 실물 기기 화면 확인 장면이다. 원본 UI 카드는 기기 외부에 배치하지 않는다. 원본 사진 A02/A04/A11은 촬영 배경 reference로 사용하며 인서트를 만들지 않는다.

## 구현

`video/src/data-insight-v2/homography.ts`는 화면 내부의 TL→TR→BR→BL 네 모서리와 평면 UI의 8변수 homography를 구하고 CSS matrix3d로 변환한다. `ScreenSurface.tsx`는 실제 source 시간 기준 track 좌표를 보간한다. 영상 레이어와 화면 합성은 동일한 1920×1080 좌표계로 배치한다. FFmpeg 번들의 filter 목록에서 perspective/overlay 필터를 확인하지 못했으므로 해당 필터를 전제하지 않았다.

원본 UI는 화면 평면 내부에만 contain 방식으로 합성한다. 화면 비율에 맞춰 UI canvas 크기와 matte 색을 정하고, 기기 베젤 안쪽 1~2px 여백을 둔 quad로 빛샘을 방지한다. 아주 약한 반사·명암 레이어를 화면 내부에만 적용하며 외부 그림자/카드 테두리는 추가하지 않는다. diagnostic의 모서리/외곽선은 검사에만 사용하고 최종 출력에는 끈다.

## 생성 소스 수용 조건

- 카메라와 화면이 고정되고, 디스플레이가 충분히 크고 온전히 보이는 OTS/사선 샷.
- 모니터/폰 내부 화면의 네 모서리를 측정할 수 있으며, 기기 화면은 프레임 바깥으로 나가지 않음.
- 손/인물이 디스플레이 활성 영역 앞을 가로지르지 않음. 가림이 있는 소스는 별도 foreground matte 없이 단순 screen warp로 통과시키지 않음.
- 화면 안에는 생성 한글이 없고, 로컬 합성할 비어 있는 디스플레이 영역이 있음.
- 화면이 과도하게 비스듬하거나 너무 작으면 원본 UI 읽기 어려우므로 합성 전에 구도를 수정 제안.

## 실제 소스가 오면

1. 소스 초반/중간/끝 및 화면 움직임 경계에서 프레임을 추출한다.
2. 생성 reference의 quad를 그대로 승인하지 않고 출력 영상의 내부 화면 모서리를 직접 측정한다.
3. 0.5초 단위 주요점과 불연속 구간에 필요한 측정점을 저장한다. 입력 형태는 `{time: source_seconds, quad:[[x,y],[x,y],[x,y],[x,y]]}`.
4. tracking quad와 실제 베젤 경계를 diagnostic still로 겹쳐 확인한다. 필요한 구간은 5~10프레임 간격으로 더 검사한다.
5. 첫 실제 장면 테스트 렌더를 독립 QA에 전달한 뒤 전체 30초 통합을 진행한다.

GIF 7프레임은 실제 기기 내부에서 전체 진행을 빠르게 보여주고, 화면 밖 별도 한글 자막에 빠르게 재생 표기를 둔다. 최종 모든 한글을 별도 inventory로 렌더 전에 확정한다. 30초 무대사 음악은 v1의 original procedural composition을 재사용한다. 최종 MP4는 50MB 미만을 기술 검증한다.

현재 단계는 수학적 좌표 변환과 편집 구조 준비다. 실제 기기 샷의 합성 품질·tracking·가림을 검수 완료한 상태가 아니다.
