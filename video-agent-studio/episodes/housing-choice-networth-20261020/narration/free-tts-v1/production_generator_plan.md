# 본편 내레이션 생성기 구현 계획

**목표:** 동일 대본 SHA의 Codex·Claude 통과 영수증이 잠금 파일로 연결된 뒤에만 무료 본문 합성을 허용한다.

**구조:** `production_narration.py`에서 대본·발음 대조표를 오프라인 준비하고, 독립 파일 `production_generate.py`가 게이트 확인 후 문단별 InJoon WordBoundary 합성·PCM 장별 조립·final_timing 생성을 담당한다. 기존 샘플과 원본은 보존한다.

**기술:** Python 3.11, 격리된 edge-tts 7.3.1, 기존 FFmpeg, PCM16 mono 24kHz.

**계약:** `director/two-episode-production-v1/media_contract.json`.

- [ ] 먼저 실패하는 계약 검사: 검수 SHA 불일치/미승인/동일 영수증 재사용 차단, 후보의 10장·54문단 추출, 금액·소수·연도 읽기, 실제 단어 경계→원문 의미구 연결, 패딩·프레임 실측.
- [ ] 승인된 추가 샘플 1회로 WordBoundary 실제 응답·원문 포함 범위·PCM 길이 확인. 원시 메타·오디오 보존.
- [ ] 발음 사전과 54문단 원문/읽기표기/대조표를 생성하되 음성 시간은 null 유지.
- [ ] 본편 생성기: 매 문단 호출 전 게이트·입력 SHA 재확인, 54회 문단 합성, 네이티브 단어 경계 기반 cue, 경계 겹침 표시만 정리. 실패는 보존하고 자동 재시도하지 않음.
- [ ] 장1 leading0.6, 이후3.5, 문단 사이0.35, 장1~9 tail1.2, 마지막은 최종 발화끝 뒤3.0. 최종 WAV를 30fps 경계로 올림하고 실측한다.
- [ ] 테스트·오프라인 준비·게이트 차단을 검증하고 handoff 갱신. 게이트 미도착이면 본문과 final_timing은 미생성으로 인계.

핵심 위험은 숫자·단위의 cue 분리, 발음 치환 후 원문 연결 손실, 서비스 경계와 PCM 신호 끝의 혼동, 대본 변경 후 낡은 승인 사용, 문단 내부를 문자 수로 시간 추정하는 것이다. 각각 실제 입력 경계 검사와 원본/메타 분리로 방지한다.
