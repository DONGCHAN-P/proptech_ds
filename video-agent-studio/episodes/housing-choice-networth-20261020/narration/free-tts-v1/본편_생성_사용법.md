# 본편 생성기와 승인 게이트

현재 준비본은 `production-prepared-v3/prepared.json`이다. 원본 후보 SHA는 `62cf5fcf06a35f3c9984de405717718fb2694ace7e1addf839b0f047055ec48d`이며, 10장·54문단의 소제목 아래 본문만 추출했다. 메타데이터와 제목은 낭독하지 않는다. 이전 준비본 v1/v2는 코드 개선 전 기록으로 보존하며 현재 코드에서 생성 입력으로 통과하지 않는다.

본문 합성은 아직 실행하지 않았다. `final_timing.json`은 실제 음성이 모두 생성·실측된 뒤에만 작성한다. `production-prepared-v3/final_timing.plan.json`은 null 타이밍을 가진 준비표이며 렌더 입력으로 사용하면 안 된다.

원문은 `source.md`에 그대로 보존했다. `pronunciation_dictionary.json`에는 이 대본에 등장한 숫자·금액·비율·연도와 S&P500/S&P/ETF의 읽기표기를 담았다. `prepared.json`의 각 문단에는 원문 위치와 낭독 위치의 대조표가 있어 화면의 숫자 표기를 바꾸지 않는다. S&P500은 “에스 앤드 피 오백”, ETF는 “이 티 에프”로 읽는다. 실제 청취와 숫자 발음 QA는 별도 단계다.

추가 샘플 1회에서 edge-tts 7.3.1의 실제 WordBoundary 7개를 받았다. 원문 전체가 경계 텍스트에 포함됐고 마지막 단어 끝 6.813166초와 PCM -60dBFS 이상 신호 끝 6.813250초를 각각 기록했다. 이 결과는 문단별 합성 경로의 지원 확인이며 본문 청취 통과가 아니다.

게이트 파일은 총괄만 작성한다. 본 담당이 승인을 추정해 만들지 않는다. episode 상대 경로를 권장한다.

```json
{
  "script_path": "writer/private-production-v1/script_v4_candidate.md",
  "script_sha256": "실제 잠근 대본 SHA256",
  "codex_receipt": "qa/private-production-v1/content_v4_review.json",
  "claude_receipt": "director/.../실제 통과 라운드/receipt.json"
}
```

두 영수증은 서로 다른 파일이어야 한다. `approved=true`, `script_sha256`/`artifact_sha256`/`checked_sha256` 중 실제 검수 SHA가 모두 잠긴 SHA와 같아야 하며 필수 이슈는 비어 있어야 한다. 기존 Claude 실행 receipt에는 필수 이슈 배열이 없으므로 동일 폴더의 `review.json`까지 대조한다. 실행 오류·내용 검수 범위 불일치·파일 누락·현재 대본 변경은 합성 전에 차단한다. 영수증 경로 대신 `{ "path": "...", "sha256": "..." }`를 넣으면 영수증 자체의 SHA도 고정한다. 규격은 `issue_GATE-SCHEMA-01.json`으로 총괄에게 인계한다.

프로젝트 루트에서 오프라인 게이트만 확인한다. 실패 시 종료코드 2이며 폴더·음성을 만들지 않는다.

```powershell
tools/python311/python.exe -B -X utf8 video-agent-studio/episodes/housing-choice-networth-20261020/narration/free-tts-v1/production_generate.py check-gate --prepared video-agent-studio/episodes/housing-choice-networth-20261020/narration/free-tts-v1/production-prepared-v3/prepared.json
```

총괄이 현재 잠금과 생성 단계 착수를 확인한 뒤 사용할 명령이다. 지금 실행하지 않았다. 새 버전 폴더만 사용한다.

```powershell
tools/python311/python.exe -B -X utf8 video-agent-studio/episodes/housing-choice-networth-20261020/narration/free-tts-v1/production_generate.py generate --prepared video-agent-studio/episodes/housing-choice-networth-20261020/narration/free-tts-v1/production-prepared-v3/prepared.json --out video-agent-studio/episodes/housing-choice-networth-20261020/narration/free-tts-v1/production-injoon-v1
```

기본 단위는 문장별 수백 회가 아니라 54문단이다. 각 문단의 원문·낭독문·원시 MP3·파생 WAV·원시 WordBoundary를 보존한다. 원문과 낭독문의 정규화 문자열이 실제 단어 메타데이터와 완전히 일치해야 한다. 의미구는 문장부호·구절과 실제 단어 경계로 묶고, 금액·숫자·단위·영문 명칭 치환을 내부에서 자르지 않는다. 하나의 실제 단어 이벤트를 공유하는 의미구는 합친다. 문자 수에 시간을 균등 배분하지 않는다. 원시 겹침은 유지하고 표시용 cue 끝만 다음 cue 시작으로 제한한다.

서비스가 SentenceBoundary만 반환하거나 단어 원문 연결이 실패하면 문단 경로를 중단한다. 이때 별도 버전의 한 문장 오디오를 실제 생성·측정하고 문장 전체 cue를 사용하거나, 추가로 실제 의미 경계를 확보해야 한다. 내부 자막을 문자 수 추정으로 확정하지 않는다. 현재 코드는 조용히 이 대체 경로로 수백 번 호출하지 않는다.

장1 leading은 0.6초, 나머지는 3.5초다. 문단 사이에는 원본의 자연 무음 외에 0.35초를 넣는다. 마지막 발화끝은 `max(마지막 네이티브 단어 끝, PCM -60dBFS 이상 마지막 신호)`라는 청취 전 추정으로 명시하고 두 값은 별도로 기록한다. 장1~9는 이 끝 뒤 최소 1.2초, 장10은 최소 3.0초를 확보한다. 원본 파일을 자르지 않으므로 이미 더 긴 무음이 있으면 유지한다. 총 길이는 24kHz PCM에서 30fps 프레임 경계로 올림한 뒤 실제 프레임 수로 다시 측정한다. 장10 마지막 3초의 무자막 CTA 유지 구간과 브랜드 인트로/아웃트로 전역 오프셋은 편집 담당이 이 타임맵을 기준으로 반영한다.

실패하면 부분 산출물과 실패 기록을 보존하고 자동 재시도하지 않는다. 명시적 `--resume`은 통과한 문단의 요청/음성 SHA와 현재 대본·음성 설정이 같을 때만 재사용한다. 합성은 시작했지만 `measured.json`이 없는 문단은 불확실 상태로 중단하며 자동 덮어쓰기·재합성을 하지 않는다. 기존 `final_timing.json`이 있으면 보존 조치를 먼저 하도록 차단한다.

최종 `final_timing.json`에는 계약의 `script_path`, `script_sha256`, `voice`, `audio_revision`, 10개 `chapters`가 들어간다. 각 장은 workspace 상대 `audio_file`, 실측 `total_seconds`, 발화끝 근거, 원문/읽기표기/문단 번호를 가진 실제 cue 배열을 제공한다. 모든 시간은 장 내부 기준이며 브랜드 삽입 이후 전역 시간은 총괄·편집 담당의 단일 오프셋 표로 연결한다. 자동 생성 사실을 실제 청취·연속 재생·최종 자막 QA 통과로 기록하지 않는다.
