# 월별 TOP20 · monthly-v2

이 버전은 월별로 갱신하고, 유효한 새 통계를 만들 수 없는 달에는 마지막으로 산출한 가격을 유지한다. 서로 다른 기준월의 가격이 함께 순위에 포함되므로 화면에 갱신 기준월과 이월 여부를 표시해야 한다. `quote`는 저장된 가격 통계를 뜻하며 매도 호가가 아니다.

## 대상과 입력

- 지역: 서울·경기·인천·부산·대구·대전·세종의 수집된 아파트. 전국 전수 자료가 아니다.
- 원거래: 유효 매매 2,153,830건, canonical 단지 12,470개. 분기 v1의 등장 후보 127개로 제한하지 않고 두 원본 Parquet 전체를 다시 읽는다.
- 전용면적: `84 <= area_m2 < 85`㎡. 매매 총액, 단위 만원/채.
- 계약기간: 2006-01-01~2026-06-30. 선행 수도권 파일의 최신 계약일이 2026-10-10이어도 2026년 7월 이후 계약은 제외한다.
- 수도권 원자료: `capital-10eok-map-20261017/research/source-completion-v1/episode_84_source_rows.parquet`. SHA256 `86b39d1800da16c87039bcaf58e3f0a1a143b2dcafb12eb8a793148b3f1399ab`.
- 확장 원자료: `analysis/housing_growth_2006/regional_expansion_v1/expansion_normalized.parquet`. SHA256 `e12a397460797b19d8ca84898a2934217871b3656fa49d21023c1f218ea80450`.

수도권은 `included_price_analysis=true`, 취소 제외, 양의 거래금액·유효일자, `complex_id=rtms:aptSeq` 조건을 적용한다. 원행 multiplicity를 유지하며 새 거래키 중복 제거를 하지 않는다. 확장은 파싱 오류·취소·fallback 또는 불명확 ID를 제외하고 `api:aptSeq`를 `rtms:aptSeq`로 통일한다. 두 입력의 시도 범위 중복이 없는지 확인한다. 대구 군위 코드 27720/47720은 모든 기간에 제외한다. 분기 v1과 단계별 제외 건수도 대조한다.

## 시드와 월별 갱신

프레임은 2006-12~2026-06의 연속된 235개 월말이다.

1. **2006-12 시드:** 2006년 전체 유효 거래가 5건 이상인 모든 단지를 초기 풀에 넣고 원거래 중위값과 거래 수를 저장한다. 12월에 거래가 없어도 포함한다. `quote_asof_month=2006-12`, `carried=false`다.
2. **2007-01 이후:** 해당 월 유효 신규 거래가 1건 이상이고, 해당 월 포함 최근 12개월의 거래가 5건 이상일 때에만 가격·표본 수·갱신 기준월을 새로 저장한다. 가격 숫자가 같아도 이 조건이 성립하면 기준월과 표본 수를 갱신한다.
3. **이월:** 이미 유효한 통계를 얻은 단지에서 새 거래가 없거나 최근 12개월 거래가 5건 미만이면 기존 가격·기존 표본 수·기존 기준월을 그대로 유지한다. 새 거래가 있어도 5건 미만이면 유지한다. 이월 기한은 두지 않는다.
4. **최초 자격 이전:** 가격을 만들지 않으며 순위 풀에 넣지 않는다. 0원 생성이나 최초 자격 이전의 역방향 채움을 하지 않는다.

중위값은 각 유효 갱신월의 12개월 창 안에 있는 **개별 원거래 금액**에서 산출한다. 짝수 표본이면 가운데 두 금액의 산술평균이다. 월별 중위값을 다시 평균하지 않는다. 창은 월초부터 마지막 월말까지며 12개월 전체를 포함한다.

순위 풀은 해당 월까지 한 번이라도 자격을 얻은 누적 단지 전체다. 가격 내림차순, 직전 월 TOP20 순위 오름차순, canonical ID 사전순으로 정렬한다. 직전 TOP20 밖의 단지는 같은 무한 순위로 처리한다. 최초 프레임의 동률은 ID로 정한다. 매 프레임 정확히 20개를 제공한다.

## 렌더용 계약

`data.json`의 루트는 `{meta, complexes, frames, summary}`다. `frames[].top`과 `frames[].top20`은 같은 20개 배열이다. `period`, `window_start`, `window_end`는 `YYYY-MM` 형식이다.

| 행 필드 | 의미 |
|---|---|
| `id` | canonical `rtms:aptSeq` |
| `name`, `display_name`, `location`, `region` | 원명, 제안 표시명, 위치, 수집 지역 |
| `median_manwon` | 마지막 유효 갱신월의 12개월 원거래 중위금액, 만원/채 |
| `n` | 마지막 유효 갱신월의 12개월 거래 수. 이월 시 그대로 유지 |
| `rank` | 해당 프레임 순위, 1~20 |
| `quote_asof_month` | 마지막 유효 통계 갱신월. 시드는 2006-12 |
| `month_new_n` | 현재 프레임 해당 월의 유효 신규 거래 수 |
| `carried` | 현재 월에 갱신하지 않아 과거 통계를 유지했으면 true |
| `stale_age_months` | 현재 월과 갱신월의 개월 차이 |
| `current_window_n` | 현재 프레임의 최근 12개월 거래 수. 이월 시 `n`과 다를 수 있음 |
| `quote_window_start`, `quote_window_end` | 표시 가격과 `n`을 실제 산출했던 12개월 창 |

`complexes`는 월별 버전에서 한 번이라도 TOP20에 든 모든 ID의 명칭·위치·건축연도와 원명 근거를 포함한다. 같은 이름의 단지는 법정동으로 구분하고 원명을 보존한다. 신규 진입은 랭킹 진입이며 준공·입주 사실을 뜻하지 않는다.

`summary`에는 전체·자격 획득·TOP20 등장 단지 수, 첫 진입/재진입·1위 교체, 프레임 전체와 마지막 TOP20 및 마지막 누적 풀의 이월 비율·평균/중앙/최대 경과 개월 수가 있다. `monthly_accounting.csv`에는 새 거래 없음과 새 거래는 있으나 5건 미만인 이월을 구분한다.

## 검증과 재현

`build_monthly.py`는 pandas로 원거래를 집계한다. `verify_monthly.py`는 집계 코드를 import하지 않고 두 원본을 다시 읽어 NumPy 원거래 정렬과 중앙값으로 전 단지·전 월을 재계산한다. 각 월의 **전체 누적 풀**에 대해 ID·가격·표본 수·기준월을 해시로 비교하므로 표시된 TOP20만 검산하는 것이 아니다. 이어 4,700개 표시 행의 가격·표본 수·순위·갱신월·새 거래 수·이월·현재 표본 수·미래 거래 배제와 중위값 양쪽 중앙 원행을 확인한다.

검증 결과는 `validation.json`, 원행 근거는 `median_evidence.csv`에 기록한다. 검증 상태가 `passed`인 결과의 `data_sha256`를 렌더 입력 해시와 연결한다. 별도 계산 알고리즘의 검산이며 제작 담당자와 독립된 QA나 실제 영상 재생·청취를 수행했다는 뜻은 아니다.


## 해석 범위

파일마다 실제 수집일이 다르다. 관측 계약 종료는 2026-06-30으로 맞추지만, 전체 거래를 같은 날 다시 조회하거나 후속 취소·수정을 전부 갱신한 자료가 아니다. 확장 자료의 기존 전처리에서 39,041개 거래키 중복이 제거되어 수도권과 원행 보존 조건에 차이가 있다. 세종은 36110 API 이력 범위이며 과거 행정구역의 완전성을 가정하지 않는다.

이월 순위는 **가장 최근 유효하게 관측한 가격의 순위**다. 오래 거래되지 않은 단지도 남으므로 현재 시장 가격이나 동일 주택 가격지수로 해석할 수 없다. 현재 시점의 최근 12개월 표본이 0건이어도 과거의 유효 표본과 가격이 표시될 수 있다. 층·동·세부 면적·거래방식·등기 여부의 구성 차이는 추가 통제하지 않았다.
