## A. 집계와 음성이 없는 다음 주제

요청: “다음 주제의 실제 집계와 음성은 아직 없다. 신혼부부 예산별 아파트 쇼츠를 먼저 어떻게 준비할까?”

### 로컬 답변 준비안

먼저 ‘같은 예산에서 어떤 동네와 아파트를 비교할 수 있는가’를 질문으로 잡고, 한 쇼츠가 답할 비교 하나를 정한다. 예산이 매매가격인지 자기자금인지부터 분명히 한다. 자기자금이라면 대출·부대비용·월 부담을 확인하기 전에는 구매 가능한 아파트를 단정하지 않는다. 현재 집계가 없으므로 순위·가격·단지 수·추천 단지는 빈 항목으로 둔다.

| 구간 | 말·화면 후보 | 필요한 입력 / 지금의 상태 |
|---|---|---|
| 도입 | “우리 예산으로 집을 찾는다면, 어떤 동네부터 비교해 볼까요?”와 비교할 예산의 정의·지역 범위 | 시험용 질문. 예산·지역 범위는 아직 미정 |
| 지역 소개 | 지역 사진과 큰 지역명으로 도착을 알린 뒤 현재 비교 대상만 보여주기 | 장소·시점·이용조건을 확인한 사진 필요. 임의 지역·사진 배정 없음 |
| 가격 비교 | 같은 전용면적·계약기간·통계 기준으로 집계한 값을 말할 때 하나씩 공개하기 | 실거래 원문, 취소 제외, 확인일, 표본 수, 중위가격/가격 구간별 단지 수의 구분 필요. 값은 미집계 |
| 마무리 | 첫 질문에 대한 확인된 답 한 가지와 이어 볼 내용 한 가지 | 다음 편의 준비·게시·관련 영상 연결 상태를 확인한 뒤 안내 문구 확정 |

문장별로 `sentence_id / 표시문 / 읽기문 / claim_id / 자료·출처 / 확보 상태 / 발화 앵커`를 준비한다. 발화 앵커는 실제 음성 뒤에 채운다. 초 단위 타임록이나 숫자 등장 시각을 미리 확정하지 않는다. ‘장보기 기능’ 대신 ‘장 볼 곳’, 일상적인 도시철도 설명에는 ‘지하철역’을 쓰되 확인하지 않은 마트·노선·시간을 덧붙이지 않는다.

화면 준비는 9:16의 도입·지역 진입·가격·마무리 네 유형을 대상으로 한다. 게시 플랫폼이 아직 정해지지 않았으므로 안전영역 프로필은 미정으로 남기고, 제작 착수 때 `config/vertical_video_safe_area.json`에서 대상 프로필을 명시적으로 선택한다. YouTube용이면 `youtube_portrait_full_frame_v2`를 적용할 수 있으나 다른 프로필 좌표와 섞지 않는다. 지금은 글자 경계나 앱 UI 모사 검사를 통과했다고 기록하지 않는다. 실제 값이 생기면 값에 비례하는 막대를 쓰고, 작은 전체표를 상시 노출하지 않는다.

다음 입력은 확정된 집계 조건·근거와 선택한 실제 음성이다. 새 유료 생성이 필요할 때만 해당 원고 버전·입력량·사용량·상한·현재 잔액·현금 결제 및 재시도 범위를 확인한다. 과거 편의 6,500크레딧 같은 상한은 복사하지 않는다. 현재는 비용 추정 수치도 만들지 않고 로컬 설계에서 멈춘다. 주제·대본·예산·완료·업로드 결정은 각각 유효한 범위로 관리한다.

### 관찰

스킬의 질문/범위 → 지역 도착 → 실제 값 공개 → 답과 후속 선택 흐름을 집계 전 준비안에 적용할 수 있었다. 실제 수치·음성·초 단위 시간표가 없어도 입력 명세와 빈 구성표를 만들 수 있었다. 과거 편 숫자와 음성을 채워 넣을 이유는 없었다.

## B. 실제 음성은 있으나 단지명이 붙어 들린다는 요청

요청: “이 편은 실제 음성이 준비돼 있다. 상계2차중앙하이츠 발음만 붙어 들리니 검토해서 반영하자.”

### 로컬 답변 준비안

수정 대상 단지명이 나오는 문장 ID와 기존 원음·읽기문·실제 시간표를 먼저 연결한다. 이 시험에서는 음성을 듣지 않았으므로 ‘붙어 들린다’는 사용자 문제 제보로 기록하고, 발음 상태를 독립 확인했다고 쓰지 않는다.

| 구분 | 유지/제안 |
|---|---|
| 원본 데이터·공식 단지명 | `상계2차중앙하이츠` 유지 |
| 화면 표시 후보 | `상계2차 중앙하이츠` — `2차` 유지 |
| 읽기문 후보 | `상계 이차 중앙 하이츠` — ‘상계 / 중앙 / 하이츠’의 단어 구분을 살리고 차수도 발화 |
| 재검수 범위 | 해당 단지명 문장과 앞뒤 문장의 호흡·편집점, 변경에 따라 움직이는 자막·컷·수치 앵커 |

원음의 해당 구간과 앞뒤 연결을 실제로 듣고 기존 읽기문·제공자 정렬과 대조할 작업을 남긴다. 띄어쓰기나 ASR 표기 일치로 자연스러움이 해결됐다고 판정하지 않는다. 단어를 잘라 이어 붙이거나 음절마다 쉼표·마침표를 넣는 방법은 기본안으로 쓰지 않는다.

새 발화가 필요하면 해당 문장의 읽기문만 버전으로 보존하고, 수정된 원고와 음성 선택에 유효한 권한·예산 범위를 확인해 해당 문장 또는 완결된 의미 단위를 다시 녹음·생성하는 방안을 맡긴다. ‘기존 음성이 있다’는 사실은 새 유료 생성 승인과 다르다. 이번 시험에서는 생성하지 않는다. ‘상계 중앙 하이츠’라는 희망 발음 때문에 원본의 `2차`를 삭제하지 않는다.

새 음성이 생기면 실제 청취로 단어 구분·억양·숫자와 다음 단어의 연결을 확인하고 실제 길이에 맞춰 자막·컷·앵커를 재정렬한다. 영향을 받지 않은 문장·원자료·사진은 재사용한다. 새 MP4의 해당 장면·앞뒤 경계·최대 줌·긴 자막과 기술 디코드를 확인하고, 표본 프레임·연속 재생·실제 청취를 각각 기록한다. 지금의 읽기문은 음성 미생성 후보다.

### 관찰

스킬의 음성 재사용 조건과 발음 가이드를 함께 적용하면 데이터 식별자·화면 표시문·읽기문을 분리할 수 있다. 읽기문이 바뀌면 기존 음성과 일치한다고 간주할 수 없다는 제한도 명확하다. 실제 청취·신규 생성·새 렌더를 했다는 표현은 쓰지 않았다.

## 연결·참조·예산 점검

자동 점검 근거는 `skill_structure_checks.json`에 저장한다. `WORKFLOW.md`의 상대 링크가 프로젝트 루트 `skills/realestate-shorts/SKILL.md`로 연결되는지, frontmatter의 이름·설명이 있는지, 스킬/참조 문서의 링크와 예시 작업 경로가 실제 작업공간 안에서 존재하는지 확인한다.

이 실행 환경의 제공 스킬 목록에는 `realestate-shorts`가 노출돼 있지 않다. 이번에는 사용자 명시 경로와 WORKFLOW 링크로 로컬 파일을 읽어 적용했다. 따라서 WORKFLOW를 통한 파일 발견과 적용은 확인할 수 있지만, 새 대화의 네이티브 스킬 자동 등록·자동 호출 성공까지 보장할 수는 없다. 실제 등록/자동 발견 확인이 필요하다면 별도 환경 확인 대상으로 남긴다.

확인한 범위에서 필수 스킬 결함은 없다. 설명의 예시 문제나 2026-11-04 참고 편을 새 편의 고정 조건으로 해석하지 않았고, 실제 음성 없는 준비안과 기존 음성의 국소 수정안 모두 작성 가능했다. 외부 최신 조사나 도구 기능의 사실 검증은 이번 로컬 시험의 범위 밖이다.
