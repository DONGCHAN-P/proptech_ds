## 단지명·읽기문과 후속 영향

원본 `P01-R11-V2-04`의 읽기문은 `상계이 차중앙하이츠`다. 이는 원문 읽기문에서 확인한 표기 문제이며 실제 음성 청취 결과라고 표현하지 않는다. 최신 문구는 데이터 식별자 `상계2차중앙하이츠`, 표시문 `상계2차 중앙하이츠`, 읽기문 후보 **`상계 이차 중앙 하이츠`**로 나눈다. 원본과 `2차`를 보존했다.

현재 `config/video_language.json`에서 보호명 우선 처리(`protected_names_before_number_normalization=true`), 기존 잘못된 읽기문 목록, 합성 전후 실제 청취 필요 조건을 확인했다. 이 QA는 해당 설정에 따른 실제 생성 파이프라인 실행이나 발음 개선을 확인한 것은 아니다.

최종 납품 확인 시 이 설정에 브랜드 보호명 `데이터로보는부동산` → `데이터로 보는 부동산` 항목이 추가됐다. 변경된 설정과 v5 읽기문의 일치, 단지명·차수 보호 및 실제 청취 조건 유지에 한정해 재검수했다. 이전/현재 SHA와 결과는 `config_delta_checks.json`에 따로 남겼다. 불변 대본·가격·순위 검사를 반복하지 않았다.

채택한다면 문장 단위로 **47개**에 새 발화가 필요하다. 영향 장면은 `INTRO-PURPOSE`, `P01-R20~P01-R11`, `P01-OUTRO`의 12개다. 기존 청크 전체를 다시 생성하는 방식을 택하면 포함 문장·입력량이 늘 수 있으므로 실제 API 입력 범위는 별도 예산안에 명시해야 한다. 미변경 43문장과 공용 CTA 2문장은 변경 대상으로 넣지 않았다.

원래 쇼츠 문장 sequence와 비교하면 홍보편 1문장, 20~16위편 3문장, 15~11위편 1문장이 겹친다. 이 정보는 변경 영향 제안이며 현재 쇼츠나 음성을 수정했다는 뜻이 아니다. 새 발화가 생긴 뒤에는 해당 문장과 앞뒤 호흡·연결, 실제 길이에 따라 움직이는 자막·컷·수치 앵커를 다시 맞춰 검수해야 한다. 기존 오디오·영상·승인 기록은 그대로다. 새 원고·예산·생성·업로드의 승인으로 이 결과를 사용할 수 없다.

## 스킬 시험과 남은 확인 범위

`skill_application_test.md`에 집계·음성 없는 새 예산별 쇼츠 준비안(A), 기존 음성의 단지명 국소 수정 준비안(B)을 작성했다. 둘 다 로컬 개요이며 승인 예시나 실제 청취 결과가 아니다. `skill_structure_checks.json`은 WORKFLOW 연결 1개, 내부 링크 5개, 예시 작업 경로 6개의 존재·작업공간 경계를 확인했다. frontmatter는 현재 두 항목의 단순한 key/value 형식으로 점검했으며 범용 YAML 전체 문법 검사를 했다고 확대하지 않는다.

현재 제공 스킬 목록에 이름이 나타나지 않아 네이티브 자동 등록은 **unchecked**다. WORKFLOW 상대 링크와 사용자 명시 경로로 파일을 찾아 읽어 적용한 것은 확인했다. 필수 스킬 결함은 발견하지 않았다. 예시 편 수치·예산·승인을 새 편에 복사하지 않는 제한도 두 개요에 적용했다. 스킬 시험 당시와 최신 대본 QA의 설정 파일 SHA는 각각의 증거 파일에 따로 남겼다.

| coverage | 상태 |

| 실제 음성 청취·ASR·신호 검사 | unchecked / 미실행 |
