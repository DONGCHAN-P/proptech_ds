# 집고리즘 서비스 검토본 실행

기존 `web/` FastAPI에 회원·예산·저장·권한 기능을 연결했다. 시안 파일 `web/design/20261019/index.html`은 독립적인 옛 디자인 시안이며 실제 서비스는 아래 서버 주소로 확인한다.

## 로컬 검토

프로젝트 루트 PowerShell에서 실행:

```powershell
$env:APP_ENV='development'
$env:JIP_AUTH_MODE='local'
tools/python311/python.exe -m uvicorn web.main:app --host 127.0.0.1 --port 8010 --no-access-log
```

<http://127.0.0.1:8010/> 예산 / `/match.html` 추천 / `/explore.html` 공개 지도 / `/saved.html` 저장함.

로컬 가입 화면에서 개발 검토용 이메일과 10자 이상 비밀번호를 입력한다. 실제 메일은 발송되지 않는다. 이 방식은 localhost에서만 허용하며 운영에서는 시작할 수 없다. 운영 데이터는 `web/runtime/service.sqlite3`에 보관하고 Git에서 제외한다. 비밀번호는 scrypt, 세션은 해시로 저장한다. 금융 원문은 사용자가 저장 버튼을 누른 예산 스냅샷에만 보관하며 일반 이벤트에는 넣지 않는다.

## Supabase 계정에서 프로젝트 연결

1. Supabase의 기존 또는 새 프로젝트를 선택한다. 유료 플랜·유료 추가 기능을 자동 신청하지 않는다.
2. 프로젝트 URL과 공개 anon API 키를 **로컬 환경 변수** `SUPABASE_URL`, `SUPABASE_ANON_KEY`에 설정한다. 비공개 DB 연결 문자열은 `DATABASE_URL`에 설정한다. 값은 채팅·Git·스크린샷에 넣지 않는다. `web/service.env.example`은 형식만 보여 준다.
3. DB 연결은 해당 환경에 맞는 Supabase 연결/풀러 옵션과 TLS 설정을 사용한다. 현재 저장 모듈은 psycopg 동기 연결이므로 도입할 풀러 모드·동시성을 실제 프로젝트에서 검증한다. 공개 API 서버에 DB 관리자 자격증명을 배포할 때는 최소 권한의 별도 서버 역할을 권장한다.
4. Auth 이메일 가입과 확인 메일, Site URL/redirect 주소를 설정한다. 이 구현은 이메일·비밀번호 로그인부터 연결하며 카카오·구글 OAuth UI, 비밀번호 재설정·탈퇴·자동 토큰 갱신은 아직 출시 범위에 넣지 않았다.
5. `JIP_AUTH_MODE=supabase`로 로컬에서 먼저 검증한다. `APP_ENV=production`은 Supabase 인증과 Postgres 설정이 모두 있을 때만 허용한다.
6. 아래 마이그레이션과 서버 테이블을 검토한다. API가 DB 소유자 권한으로 접속하는 구성은 앱의 회원 소유권 검사도 반드시 유지한다. 브라우저에 service-role 키나 DB 연결 문자열을 노출하지 않는다.

Supabase 프로젝트와 실제 자격증명이 미연결인 동안 외부 인증·Postgres·RLS 동작은 검증 완료가 아니다. 로컬 테스트 성공을 외부 연동 성공으로 보고하지 않는다. 운영은 HTTPS·호스트/프록시 설정·오류 로깅 마스킹·백업 복구·보존 삭제 스케줄·계정 탈퇴·인증 공급자 로그/메일·법적 고지·데이터/타일 이용 조건을 검증한 후 시작한다. 관리형 로그인은 서버 쿠키 세션이 15분이며 자동 갱신은 아직 미지원이다. 앱의 Bearer API는 공급자에서 사용자 토큰을 검증한다.

## 추천과 유료 권한

- 무료 개발 기본값: 하루 3회, UTC 자정(한국시간 오전 9시) 초기화. 서버에서 원자적으로 차감하고 엔진 실패는 환급한다. 후보가 0개인 정상 완료는 1회로 계산한다.
- 비회원 추천 실행과 조건별 후보 수 API는 401. 공개 단지·실거래·지도 API는 로그인 없이 이용한다.
- 예산/통근 조건을 자동 완화하지 않는다. 예산 여유 점수를 사용하며 통근은 기존 추정식과 표시용 경로 조회를 구분한다. 미래 철도를 현재 교통처럼 계산하지 않도록 운영용 역 데이터 자체의 상태 검증이 추가 필요하다.
- 유료 상품은 준비 상태의 권한 카탈로그만 있다. 실제 결제·웹훅·구독 갱신·유료 권한 부여 API·정기 리포트 생성/발송은 비활성이다. UI가 보낸 plan 값으로 권한을 변경하지 않는다.
- 추천을 저장하면 당시 입력·결과·엔진 버전·데이터 파일 시점이 스냅샷으로 남는다. 저장하지 않은 실행에는 금융·근무지 입력을 기록하지 않는다.

## 예산 계산과 참고 사이트

단위는 만원. 원리금균등과 원금균등(첫 달 상환 제한), 월 실수령 소득·생활비·기존 부채, 입력한 LTV/DSR/스트레스, 비상금과 비율·고정 비용을 함께 제한한다. 보수/기준/상한은 계산 대출 상한의 80/90/100%로 구성한다.

현재는 **사용자 가정 시뮬레이션**이다. 지역별 최신 규제·정책대출 자격·부채별 실제 DSR·세금/감면을 자동 산정하지 않는다. 비용률은 세액이 아니라 사용자가 잡은 예산이며 이사 등 고정 비용과 분리한다. 공개용 금융 정책 엔진은 공식 자료와 지원 범위 검증 후 별도 연결해야 한다.

[아는자산 계산기](https://knowingasset.com/app/calculator/housebudget)의 월 소득·지출, 상환 방식, 기간, 비용 내역·인쇄 UX를 참고했다. 계산식·세율을 검증 없이 복사하지 않았다.

## 로그·관리

```powershell
tools/python311/python.exe -m web.manage stats
tools/python311/python.exe -m web.manage prune
```

이벤트는 허용 필드만 수신하며 사용자 식별자는 검증된 세션에서 결정한다. 추천 완료는 서버가 기록한다. 요청 로그에는 라우트 템플릿·상태 코드·시간만 남긴다. 원문 body·금융 입력·토큰·쿠키·URL 쿼리·원문 IP는 제외한다. 남용 제한에는 날짜가 섞인 IP 해시 버킷을 일시 사용하며 익명화 보장으로 표현하지 않는다.

행동 이벤트 90일·요청 로그 30일은 개발 기본안이다. 시작 시와 관리 명령에서 정리하며 운영에서는 정기 실행이 필요하다. 개인 저장함은 사용자 삭제 기능을 제공한다. 공개 개인정보처리방침과 공급자/백업을 포함한 탈퇴 정책은 확정 전이다.
