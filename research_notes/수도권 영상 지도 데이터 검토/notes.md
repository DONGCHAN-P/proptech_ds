# 수도권 영상용 공용 HTML 지도와 공간데이터 검토

확인일 2026-10-15. 웹 공식 메타데이터와 이용조건을 확인한 검토다. 실제 SHP 원본 내려받기·좌표 검증·API 발급·대량 수집·웹앱 구현은 수행하지 않았다. 원본 다운로드가 검증된 것으로 읽으면 안 된다.

## 1. 공용 HTML 지도를 만들 가치가 있는가

### Takeaway
가치가 높다. 다만 ‘수도권 전체 파일을 먼저 모은 지도’보다 ‘창릉 한 편을 정확하게 만들고 왕숙·교산으로 확장하는 제작용 지도’를 권한다. 재사용할 대상은 원천 데이터뿐 아니라 위치표시·범례·날짜·출처·고정 카메라·라벨 배치와 검수 규칙이다.

### Cited Findings
- GeoPackage는 벡터·래스터 타일·속성을 SQLite 컨테이너에 담는 개방형 공간정보 포맷이다. 가벼운 단순 표시에는 GeoJSON도 적합하다고 OGC가 설명한다. 따라서 SHP를 수집 원본으로 보존하고 내부 정리본은 GPKG, 표시본은 GeoJSON으로 나눌 기술적 근거가 있다. [OGC](https://www.geopackage.org/)
- MapLibre 공식 예제는 PMTiles 프로토콜을 등록해 벡터 타일 지도를 표시한다. 넓은 지역으로 커질 때 PMTiles를 도입할 선택지가 있다. 처음부터 이를 필수로 만들 필요는 없다. [MapLibre](https://maplibre.org/maplibre-gl-js/docs/examples/pmtiles-source-and-protocol/)
- 공공누리 1유형은 출처표시로 상업 이용·변경 가능, 2유형은 상업 금지, 3유형은 변경 금지, 4유형은 두 제한을 함께 둔다. 정부 자료라는 이유만으로 수정·수익화 영상 사용이 일괄 허용되는 구조는 아니다. [공공누리](https://www.kogl.or.kr/info/license.do)
- OSM 공용 타일 서버는 데이터 라이선스와 별도로 대량 선취·오프라인 저장·자동 팬/줌을 통한 타일 수집을 금지한다. 단순 캐시 의무와 오프라인 아카이브 허용은 다르다. [OSMF 타일 정책](https://operations.osmfoundation.org/policies/tiles/)

### Inferences
- 권고 구조: 보존 원본(SHP ZIP/CSV/PDF와 취득일·해시) → QGIS/GDAL로 정리한 지역별 GPKG → 표시용 GeoJSON(필요할 때만 PMTiles) → MapLibre HTML → 장면별 PNG/영상 렌더. HTML 검토와 Remotion 최종 출력은 같은 scene JSON을 읽게 해 재배치 차이를 줄인다.
- 초기에는 외부 배경 타일 없이 직접 보유·이용 허용이 확인된 행정경계·도로·하천을 단순화해 보여주는 방식이 재현성과 비용 예측에 유리하다. OSM을 쓰면 ODbL/표시 의무를 별도 확인하고, 타일은 자체 구축 또는 오프라인·영상 렌더를 명시 허용한 공급자를 선택한다.
- 고정 카메라 장면을 기본으로 한다. 상세 설명에는 좌측 해당 지구 전체계획 한 장과 현재 범위 사각형, 중앙 대형 지도, 지도 위 짧은 요약, 하단 가로 타임라인을 조합한다. 기존 사용자 지시대로 반복 줌·순간 전체화면 삽입은 기본에서 제외한다.
- 제작시간 절감은 기대할 수 있으나 절감률·구현 일수·GB·API 총비용을 측정하지 않았으므로 수치로 보장하지 않는다. 범위가 커질수록 원천 정합·갱신·권리 확인 작업은 계속 필요하다.

### Gaps
- MapLibre 기술 지원과 원천 데이터 이용권은 별개다. 브이월드 API 이용약관 원문은 웹 접근 오류로 이번에 읽지 못했다. 상업적 지도 이미지 출력, 로컬 저장, 재제공, 영구 캐시 허용은 API 사용 전 현행 약관·승낙을 확인해야 한다.
- 지도 플랫폼은 데이터 오류를 자동 해결하지 않는다. 특히 예정역을 예쁜 점으로 찍는 행위가 위치 확정의 근거가 되지 않는다.

## 2. 어떤 데이터를 어디서 받을 수 있고 무엇을 혼동하면 안 되는가

### Takeaway
SHP만으로 영상에 필요한 정보가 완성되지 않는다. 현재 지형·역·상가는 공개 벡터/CSV를 쓰고, 신도시 블록·계획학교·계획역·개통 일정은 최신 사업 도면·고시·공고로 별도 연결해야 한다.

### Cited Findings
- **상가**: `소상공인시장진흥공단_상가(상권)정보_20260630`, CSV/ZIP UTF-8, 전국 업소 상호·업종·주소·경도·위도, 분기 갱신, 2026-08-05 등록/수정, 다음 예정 2026-10-31. 무료·이용허락 제한 없음이 메타데이터에 명시돼 있다. 원문이 ‘영업 중’ 자료여도 촬영일의 개별 점포 영업을 실시간 보증하는 자료로 확대하면 안 된다. [공공데이터포털](https://www.data.go.kr/data/15083033/fileData.do)
- **현재 역**: `국가철도공단_철도역 정보_20250711`, CSV 및 변환 JSON/XML API. 주소·위도·경도·관련 노선 제공, 연간 갱신, 다음 예정 2026-11-30, 파일 215행으로 표시, 무료·제한 없음. 파일은 로그인 없이 내려받기 가능, 변환 API는 회원가입/활용신청 필요. 모든 수도권 도시철도와 모든 출입구를 포괄한다고 가정하지 않는다. [공공데이터포털](https://www.data.go.kr/data/15067652/fileData.do)
- **서울 교통 역마스터**: 서울시 역사마스터 OA-21232, 역사ID·역명·호선명·좌표 제공. 현행 페이지 갱신일 2026-10-12, 수시, KOGL1. Sheet/OpenAPI 경로이며 첨부 파일 목록은 ‘파일 없음’으로 보였다. 페이지의 CSV 내려받기 안내와 오래된 포털 CSV 메타데이터를 구분해야 한다. 실제 API 호출·범위·좌표계 값 검증은 미실행. [서울열린데이터광장](https://data.seoul.go.kr/dataList/OA-21232/S/1/datasetView.do)
- **토지이용 규제/계획 API**: `국토교통부_토지이용계획정보(WMS/WFS/속성정보)` 15123973. 연속지적도와 토지이용계획정보를 융복합한 자료, JSON/XML/LINK, 무료·제한 없음, 실시간 갱신으로 표시. 개발 자동승인/운영 심의승인, 트래픽은 기관 정책. 이는 LH 신도시 전체 블록별 분양·학교·상업 배치계획을 완성해 주는 파일이라는 뜻이 아니다. [공공데이터포털](https://www.data.go.kr/data/15123973/openapi.do)
- **도로**: `국토교통부_도로(현황)_20250625` 15125057, SHP, 월간, VWorld dsId=30074 연결, 무료지만 **KOGL4**. 이 파일을 수익화 영상의 가공 배경으로 바로 채택하지 않는다. [포털](https://www.data.go.kr/data/15125057/fileData.do?recommendDataYn=Y)
- **용도지역 예시**: `국토교통부_(연속주제)_산업집적활성화및공장설립_용도지역_20250814` 15147059, SHP/수시/무료, **KOGL4**. ‘용도지역’이라는 비슷한 이름으로 다른 데이터의 라이선스를 옮겨 적지 않는다. [포털](https://www.data.go.kr/data/15147059/fileData.do)
- **신도시 계획도**: LH 3기신도시 창릉 토지이용계획 페이지는 현재 ‘내집어디’에서 사업지구를 선택해 확인하라고 안내한다. 이 페이지 자체에서 다운로드 가능한 SHP를 확인한 것은 아니다. 계획도와 고시 첨부, 블록별 공고를 함께 보아야 한다. [LH 창릉](https://www.xn--3-3u6ey6lv7rsa.kr/kor/CMS/Contents/Contents.do?mCode=MN077)

- **철도망 보완**: KTDB 2025 공개 보고서는 실제 철도노선도·거리표 변경고시·운영사 시각표를 수집해 네트워크를 갱신했다고 설명한다. 전국 철도망도 원천 교차검증과 기준시점 관리가 필요한 자료임을 보여준다. 보고서 설명과 현행 배포 SHP 이용허락은 별개다. [KTDB 공식 보고서](https://www.ktdb.go.kr/DATA/pblcte/20250805092141083.pdf)

### Inferences
- 구분 ① 연속지적도=필지 경계 참조 ② 용도지역/지구=법적 토지 이용 규제 ③ 신도시 사업 토지이용계획=예정 도로·공원·학교·주거 블록 배치. 서로 대체하지 않는다. 지구의 A1·B17은 기존 지번을 읽어서 자동 생성할 수 없다.
- 현황 역 중심좌표와 출입구 좌표도 구분한다. 현황 노선망을 계획역/신설 노선의 위치 증거로 쓰지 않는다. 계획역은 원출처 도면에서 좌표화 가능한 경우에도 `approximate`와 도면 버전을 기록하고, 부정확하면 중심 점 대신 예상 구간/영역으로 표현한다.
- CSV 경도/위도라고 해서 모든 파일의 EPSG:4326을 확인한 것으로 기록하지 않는다. SHP는 `.prj`를 읽고 Bessel/GRS80 및 원점을 검증한다. 내부 거리·면적 계산은 적정 미터 좌표계로 통일하고 웹 표시 단계에서 WGS84 경위도/지도 투영으로 변환한다. 임의 CRS 지정은 금지한다.
- 학교 ‘계획용지’와 개교 확정일, 상업 ‘용지’와 실제 입점, 자족 ‘면적’과 기업 확정 입주를 서로 다른 레이어/주장으로 관리한다.
- 경기도 데이터드림 검색은 이번 제한된 조사에서 정확한 철도/토지계획 데이터셋까지 특정하지 못했다. 포털 이름만 카탈로그에 넣고 확보 완료로 부풀리지 않는다.

### Gaps
- VWorld 연속지적도 최신 다운로드 페이지/라이선스/CRS·갱신은 직접 페이지 접근 실패로 미확정. 과거 자료의 좌표계·월간 주기를 현행 사실로 승격하지 않는다.
- 창릉·왕숙·교산 최신 고시 도면의 원본 벡터(SHP/DWG/GPKG) 공개 여부와 재가공 권한, 각 계획역 설계 중심/출입구, 학교 개교·입점 날짜는 추가 확보 대상이다.
- 공공누리3 자료의 확대·부분 잘라쓰기·오버레이 등 구체 사용이 허용되는지 이번 조사만으로 법률 판단하지 않는다. 원본 보존 + 별도 해설 레이어라는 구분만으로 자동 해결된다고 보지 않는다.

## 3. 다음 영상에 적용할 최소 범위와 운영 기준은 무엇인가

### Takeaway
창릉 중심 한 지역팩을 먼저 만들고 동일한 장면 명세를 왕숙·교산에 적용하는 단계가 적절하다. 승인받은 사용자 가이드대로 지도 정확도·자막·타임라인을 대표 장면에서 확정한 뒤 전체 편집에 쓴다.

### Cited Findings
- GPKG는 공간 피처와 비공간 속성을 함께 저장하고 갱신할 수 있다. 원본 버전과 검증 상태를 관리하는 저장소로 적합한 기술 기반이다. [OGC](https://www.geopackage.org/)
- MapLibre는 PMTiles 소스를 통한 지도 표시 예제를 공식 제공하므로 데이터가 커졌을 때 표시 포맷 확장이 가능하다. [MapLibre](https://maplibre.org/maplibre-gl-js/docs/examples/pmtiles-source-and-protocol/)
- 계획도 직접 확인 진입점은 LH 창릉 공식 안내에서 확보된다. 전 수도권 SHP 수집을 기다리지 않고 다음 편의 지역 단위 계획 확인을 시작할 수 있다. [LH](https://www.xn--3-3u6ey6lv7rsa.kr/kor/CMS/Contents/Contents.do?mCode=MN077)

### Inferences
1. **창릉 데이터팩**: 지구 경계·주거 블록·상업/자족·공원·학교 계획용지, 기존 지하철/역, 신설 철도 예상 구간, 기존 주변 생활시설, 주변 비교 단지. 도면이 래스터뿐이면 지리보정 이미지 레이어를 쓰고 정밀 벡터인 척 만들지 않는다.
2. **최소 장면 템플릿**: 수도권 위치 / 지구 전체 배치 / 권역 상세+작은 전체계획 / 철도 현재와 미래 / 지도+가로 일정 / 비교 단지가격. 장면마다 보이는 레이어가 달라야 하며 본문과 무관한 같은 지도 반복을 막는다.
3. **명세 분리**: `sources`(URL·해시·기준일·취득일·라이선스), `features`(지구명 포함 ID·geometry·좌표계·현황/공사/승인계획/제안·정확도), `events`(착공/입주/개통/개교·확정/목표·최초사용시점), `scenes`(고정bounds·표시레이어·라벨·locator범위·출처)로 나눈다. 왕숙1 A1과 왕숙2 A1처럼 지역을 포함한 고유키가 필요하다.
4. **필수 검수**: 지도와 inset이 같은 지구인가, 내레이션 시점에 해당 영역인가, 현재역/계획역 모양이 다른가, 노선/라벨이 겹치는가, 글자 bbox+외곽선이 안전영역에 드는가, leader가 정확한 대상에 닿는가, 숫자·면적·단위가 의미 단위로 유지되는가. 시작/끝 프레임과 전환 양쪽을 검사해 한 프레임 삽입을 막는다.
5. **확장 순서**: 창릉 대표 장면을 검토한 뒤 왕숙 최종의 검증된 도형·레이아웃을 이식하고 교산을 더한다. 지역이 늘고 로딩/메모리를 실제 측정해 병목이 있을 때 벡터 타일/PMTiles를 도입한다.
6. **갱신 규칙**: 원천 제공 주기와 별개로 영상 확정 전 중요한 역·개통·입주·청약 공고는 재확인한다. 원본은 날짜 스냅샷으로 남겨 지난 영상이 어떤 근거로 제작됐는지 재현한다. 데이터 업데이트를 과거 영상 장면에 자동 덮어쓰지 않는다.
7. **비용과 보관**: 첫 구축은 데이터 정리·권리 확인·변환 검수 비용이 들고 다음부터 스타일·장면 재사용 이득이 생긴다는 상대 평가다. 실제 용량/개발시간/요금은 파일 표본과 API약관 확인 뒤 측정한다. 필요한 지구와 주변 비교권역만 절단해 보관하고, 데이터 원본/최종 출처와 대형 재생성 캐시를 구분한다.
