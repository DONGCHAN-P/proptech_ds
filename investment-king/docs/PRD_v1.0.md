## 0. Executive Summary

**나는야 투자왕**은 2006년 대한민국의 스무 살 청년으로 돌아가 현금 100만 원을 가지고 인생을 다시 살아보는 **실제 역사 기반 투자 × 인생 선택 × 로그라이크형 시뮬레이션 게임**이다. 플레이어는 시장의 미래를 어렴풋이 기억하지만, 돈·시간·지식·신용·투자 접근성의 한계를 갖는다. 시장 가격은 역사 데이터에 고정되지만 캐릭터의 경력, 건강, 관계, 개인 운명은 선택과 시드에 따라 달라진다.

### 확정된 제품 결정

| 의사결정 | 확정 내용 |
|---|---|
| 게임 이름 | 나는야 투자왕 |
| 메인 모드 | 기억의 파편: 미래에 관한 불완전한 힌트만 보유 |
| 시간 단위 | **1턴 = 1분기 = 3개월** |
| 총 턴 | **80턴** |
| 시점 | **2006-Q4부터 2026-Q3까지 80개 분기**; 마지막 턴 정산은 2026-Q3 말, 엔딩은 2026-Q4 입구에서 표시 |
| 초기 상태 | 만 20세, 현금 1,000,000원, 무직, 무주택, 가족과 동거(기본 난이도) |
| 우선 목표 | **경제적 자유와 삶의 만족도를 균형 있게 높이기** |
| 시장 | 한국 주식/해외 주식, 부동산, 비트코인·이더리움, 금, 예적금·현금 순차 지원 |
| 게임 플랫폼 | PC/모바일 웹 우선, 앱은 후속 검토 |
| 주 사용 언어 | 한국어, 금액 원화 표시 |

> **시간 경계 정의**: 2006-Q4 ~ 2026-Q3는 80개 분기를 정확히 포함한다. 매 턴 말에 3개월이 경과하며, 80턴 직후 2026-10-01 시점으로 엔딩한다. 시작 시 만 20세인 인물은 정확한 생일 설정을 하지 않는 MVP에서 경과 개월로 나이를 표시한다(엔딩 시 약 40세). **게임 내 시가 데이터의 종료 기준은 2026-09-30**이다.

### 제품 가치 제안
1. 20년을 다시 살아보는 **후회의 재구성**: '그때 샀더라면?'을 경험한다.
2. 시간과 노력도 자산이라는 **의사결정 시뮬레이션**: 취업, 공부, 건강, 관계가 투자와 연결된다.
3. 실제 과거 데이터에 기반한 **시장 복기**: 과거 가격 변동과 현실적인 제약을 경험한다.
4. 반복할수록 다른 경로를 발견하는 **리플레이성**: 이벤트 시드, 인생 선택, 학습 순서에 따라 전략이 달라진다.

## 1. 문제 정의·타깃·포지셔닝

### 유저의 문제
- 과거 금융·부동산 이벤트에 대해 막연히 '알았더라면 부자가 됐을 텐데'라고 생각하지만 당시의 자금·정보·접근 제약을 체감하기 어렵다.
- 금융 교육 콘텐츠는 수동적이고, 순수 투자 게임은 취업·주거·가족 같은 현실적 기회비용을 충분히 다루지 않는다.
- 실시간 투자 상품의 과열·손실 위험 없이 역사 속 전략을 실험할 게임이 부족하다(시장조사로 검증할 가설).

### 주요 페르소나
| 페르소나 | 동기 | 핵심 기대 |
|---|---|---|
| A. 20~30대 금융·게임 관심층 | 비트코인/집값/주식 '그때'의 상상 | 역사 기반 투자, 낮은 진입장벽 |
| B. 인생 시뮬레이션 애호가 | 커리어·연애·주택·가족 선택 | 유의미한 관계와 삶의 결과 |
| C. 전략·로그라이크 유저 | 다른 빌드의 최적화 | 재현 가능한 규칙, 시드 도전 |
| D. 콘텐츠 크리에이터 | 공유 가능한 반전 서사 | 인생 카드, 랭킹, 비교 그래프 |

### 제품 약속
> **돈을 가장 많이 번 사람이 무조건 승리하는 게임이 아니다.** 돈은 자유를 만들지만 건강·가족·시간을 모두 희생한 플레이에는 분명한 비용이 존재한다.

### Non-goals / 하지 않는 것 (v1)
- 실제 투자 중개·실제 매수/매도 및 금융계좌 연동
- 실제 플레이어 사생활을 입력받아 자산·결혼·자녀를 자동 추정
- 일 단위 초단타, 파생·신용거래 무제한, 공매도, 옵션
- 전국 모든 개별 부동산 실거래를 언제든 동일 가격에 즉시 매수할 수 있게 만드는 기능
- NFT, 토큰, 실제 현금 보상을 통한 투기성 경쟁
- 인간관계·출산을 의무적 '성공 조건'으로 만드는 시스템

## 2. 핵심 UX·플레이 흐름

### 2.1 온보딩 (최대 목표 3분)
1. 표지: '20년 전으로 돌아간다면, 나는 부자가 될 수 있을까?'
2. 세계관: 2006년 / 나이 20 / 현금 100만 원 / 흐릿한 미래 기억
3. 캐릭터 생성: 이름/아바타/플레이 취향(투자 중심·인생 중심); 능력치는 동등한 기본값
4. 기억의 파편 카드 2장 획득(정확한 매수 가격·날짜·종목 추천은 없음)
5. 튜토리얼: 통장→행동력 3→알바/공부→분기 진행→손익 정산
6. 첫 턴 시작

### 2.2 분기 반복 코어 루프
```
분기 시작(역사 시점 스냅샷)
 → 현재 시점에서 알려진 뉴스·자산·관계·직업 확인
 → 행동력(AP) 3개 이내로 인생 행동 예약/즉시 실행
 → 거래 및 예적금·주거 선택(행동력은 원칙적으로 불소모, 거래비용·제약 적용)
 → 다음 분기 버튼
 → 월별: 급여·세금(단순화)·생활비·부채·이자·계약 정산
 → 역사 이벤트와 개인 이벤트 발동
 → 분기 말 가격 평가 및 능력치·관계·성취 갱신
 → 인생 일지/변동 요약/새 분기로 이동
```

### 2.3 게임 홈 화면 IA
- 상단 고정: `2006-Q4`, `20세`, `현금`, `순자산`, `인생 만족도`, `행동력(3/3)`
- 중앙 탭: **인생** | **투자** | **부동산** | **기억과 뉴스** | **내 기록**
- 하단 주요 CTA: `다음 3개월`(불가역 확정 전 미처리 알림과 예상 현금흐름 표시)
- 알림: 마이너스 현금 예상, 매수 불가 이유, 만기, 취업 결과, 시점 한정 기회

### 2.4 핵심 화면 목록·완료 조건
| ID | 화면 | 주요 인터랙션 | 완료 조건 |
|---|---|---|---|
| SCR-01 | 시작/모드 선택 | 시작, 튜토리얼 | 60초 내 게임 진입 가능 |
| SCR-02 | 내 삶 대시보드 | 행동, 능력치, 관계 | 생존비·행동력·현재 상태가 동시에 보임 |
| SCR-03 | 투자 장터 | 종목 탐색, 투자금 입력, 매수·매도, 그래프 | 거래 가능 시점/수수료/수량 제약 명시 |
| SCR-04 | 부동산 | 지역 매물, 전월세, 매수, 대출 계산 | 자기자본·월 상환·잔금 유동성 미리보기 |
| SCR-05 | 이벤트/기억 | 뉴스, 선택지, 기억 조각 | 시점 이후의 확정 정보 노출 없음 |
| SCR-06 | 분기 결산 | 순자산 변동, 소득·지출, 사건 타임라인 | 무엇 때문에 변했는지 설명 가능 |
| SCR-07 | 엔딩 성적표 | 종합 점수, 인생 이력, 공유 | 재현 가능한 엔딩, 공유 이미지 |
| SCR-08 | 이전 생 비교 | A/B 회차 비교 | 동일 조건 차이와 시드 차이 구별 |

### 2.5 투자·인생의 긴장 관계 예시
- 금융지식 책을 읽으면 투자 위험과 보유 종목 이해도가 상승하지만 그 분기의 아르바이트 기회를 잃는다.
- 직장을 다니면 안정적 수입과 신용이 쌓이나 행동력과 스트레스 관리가 어려워진다.
- 결혼과 육아는 비용·시간·관계를 함께 바꾼다. 플레이어는 결혼하지 않거나 자녀를 갖지 않을 자유가 있다.
- 2008 금융위기 때 현금 여력이 있으면 매수 기회가 생기지만, 고용 불안정이 있다면 비상자금을 우선해야 할 수 있다.

## 3. 제품 요구사항 (P0/P1/P2)

### 3.1 P0 — 첫 공개 가능한 MVP
| ID | 요구사항 | 수용 기준 |
|---|---|---|
| P0-01 | 2006-Q4~2026-Q3까지 80턴 엔진 | 정확히 80회 커밋 후 엔딩, 오프바이원 없음 |
| P0-02 | 100만 원 현금 시작 및 월별 현금흐름 | 매 수입·지출이 현금원장과 일치 |
| P0-03 | 행동력 3개/턴 | 초과 수행 금지, 분기 단위 초기화 |
| P0-04 | 직업/알바/공부/휴식/관계 행동 | 능력치·현금·상태 변화 및 로그 |
| P0-05 | 실제 역사 주식 6종·금·현금/예적금·BTC(가능 시점 이후) | 가용 시작 시점 위반 거래 불가, 데이터 품질 표시 |
| P0-06 | 지역 단위 부동산 4~6개 시나리오 매물 | 가격·대출·거래비용·잔금 검증 |
| P0-07 | 역사 이벤트 12~15개 + 개인 이벤트 20~25개 | 역사 이벤트 시점 고정, 개인 이벤트 시드 재현 |
| P0-08 | 기억의 파편 | 힌트 2장 시작, 총 최대 5장; 정확한 미래 가격 누출 없음 |
| P0-09 | 순자산 및 삶의 점수 별도 산출 | 계산 근거 표시 및 극단값 테스트 통과 |
| P0-10 | 자동저장/재접속 | 턴 커밋 후 재개 가능, 중복 결산 방지 |
| P0-11 | 엔딩 요약/다시 하기 | 80턴 완료·비교·공유 카드 1개 |
| P0-12 | 시장가격·이벤트 지식 차단 | as-of 검증 테스트 통과 |

**P0 자산 범위는 데이터 확보 후 확정**한다. 데이터 출처 또는 재배포 권한이 미해결된 종목은 P0에서 제외·대체하며, 실제 가격으로 위장한 가상 데이터를 쓰지 않는다.

### 3.2 P1 — 재미 심화
- 취업·이직 세부 트랙(대기업/IT/공무원/자영업/프리랜서)
- 해외주식 환전과 원화 기준 손익, 배당, 액면분할
- 배우자 성격/직업/맞벌이, 육아·휴직·돌봄 구조
- 대출 상환 방식과 시대별 대출 제약 세분화
- 동등 시드 챌린지 및 시드별 리더보드
- 튜토리얼 건너뛰기, 속도 모드, 키보드 단축키
- 해금 업적·도전과제, 리플레이 메타 진도(경제적 보너스 없음)

### 3.3 P2 — 확장
- 개별 아파트·동네 탐색, 청약·임대·재건축 시나리오
- 창업/부업 경제 시스템, 물가/사치/교육비 정밀모델
- AI 생성 내러티브(상태 검증 후 표현만, 게임 결과 판정은 룰엔진)
- 추가 시대: 1997~2017 외환위기 시나리오, 국가별 모드
- 유저 제작 챌린지·시나리오 공유

## 4. 캐릭터 시스템

### 4.1 상태 축
- 6개 핵심 능력치: `financial_knowledge`, `career_skill`, `execution`, `health`, `relationship`, `credit` (0~100)
- 동적 상태: `stress`, `happiness`, `autonomy` (0~100), `occupation`, `occupation_level`, `employment_status`, `partner_state`, `children_count`, `housing_state`, `cash`, `liabilities`, `portfolio`
- 감추어진 값: 이벤트 시드, 이벤트별 난수 추첨, 개인 성향 태그(선택 가능), 미래 기억 해금 진행

### 4.2 기본 제공 행동 (3 AP/턴)
| 행동 | AP | 직접 결과 | 장기적 효과 |
|---|---:|---|---|
| 단기 알바 | 1 | 당분기 소득 증가, 피로 증가 | 현금 확보 |
| 전공·직무 공부 | 1 | 직무능력 증가 | 취업·승진 자격 |
| 금융 책 읽기 | 1 | 책값 지출, 금융지식 증가 | 투자 정보 해금 |
| 운동·휴식 | 1 | 건강 회복, 스트레스 감소 | 삶의 점수·행동 효율 |
| 취업 지원 | 1 | 확률 평가·합격/불합격 | 정규 월급 해금 |
| 이직·승진 준비 | 1 | 직업 레벨·소득 기회 | 중장기 수입 상승 |
| 교류·데이트 | 1 | 관계도 증가, 이벤트 | 관계 선택지 해금 |
| 부업·사업 준비 | 1 | 초기비용/실행력 소모 | 비정기 수입 기회 |

- 전업 직장의 급여는 **수동적 월별 유입이 아니라 근로계약에 따른 고정 소득**으로 분기마다 정산한다. AP 3은 일상 외에 플레이어가 배분하는 **재량 시간**이다.
- 직업별 추가 AP 제한을 둔다면 v1.1부터 적용하고, 첫 MVP는 각 분기의 AP 3을 고정한다(진입 난이도 감소).
- 거래 UI에서 매수·매도는 AP를 쓰지 않되, 시장 접근/수수료/매수 한도/거래 빈도 제한이 존재한다.

### 4.3 관계·가족·주거
- 결혼·출산은 자발적 선택이며 경제적 성공의 전제 조건이 아니다.
- 배우자/파트너는 월 소득, 지출 분담, 주거 선호, 대화 이벤트를 생성할 수 있다.
- 관계도 0~100; 관계 악화는 대화/갈등 이벤트를 만들되 무작위 파국으로 갑자기 끝나지 않도록 경고 신호를 제공한다.
- 육아는 생활비·재량 행동 기회와 연결될 수 있으나 상벌식의 도덕 점수는 도입하지 않는다.
- MVP에서 주거 형태: 가족 동거, 월세, 전세, 자가. 각 유형에 월비용/보증금/자산화/부채 영향이 있다.

## 5. 투자·경제 시스템 요구사항

### 5.1 자산 클래스
- 주식: 국내/해외 상장 시점·거래가능 시점, 매수단위, 배당, 기업행위, 상장폐지; 원화 기준 평가.
- 암호화폐: BTC는 2009년 네트워크 등장 이후; 실제 접근 가능한 시장/거래소·유동성 확인 후 거래 해금. ETH는 2015-07-30 네트워크 출범 이전 현물 거래 금지.
- 금: 2006년엔 실물 금 옵션(프리미엄·보관), KRX 금시장은 2014-03-24 이후 별도 수단.
- 예적금: 당시 금리 시계열 기반의 가상 상품; 복리·중도해지/만기 구분.
- 부동산: 지역/면적/유형 수준의 실거래 기반 가상 매물. 같은 지역 평균가격에 항상 무한 매수하는 방식 금지.
- 현금: 명목 원화 및 CPI 기반 실질 구매력 표시.

### 5.2 거래 제약
1. 시점 이전에 존재하지 않는 상품 거래 불가.
2. 역사 가격 조회는 `현재 턴 시점` 이전 데이터만 허용.
3. 원 단위 현금원장/수량 정밀도 구분: 주식 정수 주, 코인 소수 수량.
4. 시장별 수수료, 환전 스프레드, 세금, 슬리피지 적용(역사 고증 수준별 설정).
5. 주문은 **다음 거래가능 세션의 실행가격**으로 체결되며 사용자는 미래 실행가격을 미리 확인할 수 없다.
6. 극초기 코인과 소형주에 회당 유동성 상한 및 시장충격 또는 거래불가 상태 적용.
7. 매수 주문 후 현금 부족, 잘못된 로트, 거래불가 상태는 명확한 오류를 보여준다.
8. 부동산은 자기자본·취득비·대출 한도·월부채상환 조건 충족 시 매수 예약 가능.

### 5.3 경제적 곤란 처리
- 생활비가 부족하면 우선 자유 현금을 사용하며, 부족액은 **미납·체납 상태**로 기록한다.
- 첫 경고에는 플레이어에게 알바·지출감소·보유자산 매도를 안내한다.
- 자동으로 모든 주식·금·코인을 강제 매도하지 않는다. 강제청산은 계약·파산 이벤트에 명시된 경우에만 적용.
- 경제적으로 실패한 뒤에도 구직/생활복구 이벤트를 통해 게임을 끝까지 이어갈 수 있도록 한다.

## 6. 기억의 파편·뉴스·이벤트

### 6.1 기억의 파편 원칙
- 첫 시작 2개, 플레이 과정 최대 3개 추가(한 회차 최대 5개).
- 기억은 특정 자산의 정답이 아니라 **경제적·기술적 테마**를 암시한다.
- 예: '인터넷에서 만들어진 낯선 화폐가 언젠가 뉴스의 중심에 설지도 모른다.'
- 기억만으로 거래가 자동 해금되지 않으며 정보 탐색·기술 지식·시장 접근 조건이 필요하다.
- 전 회차의 기억 해금이 다음 회차에서 직접적인 선행 투자 혜택으로 이전되지 않는다.
- 모든 파편은 역사 사실과 양립하도록 감수. 가격과 거래 시점의 확정 미래 예고는 금지.

### 6.2 이벤트 종류
**역사적 고정 이벤트**: 글로벌 금융위기, BTC 출범, KRX 금시장 개설, ETH 출범, 팬데믹 등. 사건의 발생 시기·가격은 역사적으로 고정. 다만 **게임에 실제 기사가 노출되는 시점**은 그 당시 공개 시점을 지킨다.

**개인 확률 이벤트**: 면접 합격, 승진, 해고, 건강 문제, 투자 사기 접근, 가족과의 일정 충돌, 우연한 기회. 기본 확률은 캐릭터 능력치·상태·기존 이벤트 영향을 받는다.

### 6.3 이벤트 예시(게임 내 창작)
- 2008 Q4: `회사에 구조조정 소문이 돌고 있다.` → 구직 준비 AP를 미리 투자했으면 위험 완화.
- 2010~2012: `커뮤니티에서 새로운 인터넷 화폐 관련 게시글 발견.` → 금융지식/IT경험 충족 시 조사 이벤트 노출.
- 2020 Q2: `불확실성 속에서 이직과 투자를 동시에 결정해야 한다.` → 건강/소득/현금에 따라 선택지가 달라짐.

## 7. 스코어·엔딩·리플레이

### 7.1 두 개의 성적표
1. **경제 성적표**: 명목 순자산, CPI 조정 실질 순자산, 투자 기여 수익, 총 노동 소득, 부채비율, 경제적 자유 지수.
2. **인생 성적표**: 건강, 관계, 자율성, 행복, 주거/생활 안정의 합성점수.

### 7.2 공식 점수 (MVP 가설)
- 자산점수: `100 × clamp(ln(1 + max(순자산,0)/1,000,000) / ln(1 + 3,000,000,000/1,000,000), 0, 1)`
- 삶의 점수: `0.30×건강 + 0.25×관계 + 0.20×자율성 + 0.15×행복 + 0.10×안정`
- **균형 점수**: `0.50×자산점수 + 0.50×삶의 점수`
- 현금흐름에 따른 경제적 자유 지수는 별도로 제공하며 순자산과 혼동하지 않는다.
- 위 수치/30억 기준은 **초기 밸런스 가설**이다. 봇 시뮬레이션과 플레이테스트를 통해 조정한다.

### 7.3 엔딩
- 경제 엔딩: 생존자, 안정형, 자산가, 투자왕 등 (구간은 실제 플레이 분포로 조정)
- 인생 엔딩: 배움의 인생, 관계 중심, 일 중심, 시간의 자유 등 (도덕적 우열 없음)
- 특별 서사: 2008 폭락기 복구, 첫 내 집, 비트코인 보유와 매도, 재취업 성공 등
- **엔딩 화면 필수**: ① 순자산 ② 삶의 점수 ③ 자유 지수 ④ 자산 그래프 ⑤ 중요한 인생 선택 Top 3 ⑥ 전생 비교 ⑦ 공유 카드 ⑧ 다시 플레이.

### 7.4 랭킹 공정성
- 경쟁 랭킹은 **공식 시드·공식 데이터 버전·동일 시작 조건·동일 모드**만 참여.
- 자유 플레이/디버그/미래 시세 열람 모드는 랭킹에서 제외.
- 시장 데이터 패치가 발생하면 시즌/데이터버전별 랭킹을 분리.
- 서버 검증된 행동 로그와 턴별 상태 해시로 위변조 검사.

### 8.2 데이터 품질 요구사항
- 모든 시세 레코드: `source`, `source_date`, `retrieved_at`, `asset_id`, `timestamp`, `price`, `currency`, `quality_flag`, `license_status`, `dataset_version`.
- `price`가 없을 때 0으로 치환하지 않는다. **거래 정지·미제공·시장 미개설**을 구별한다.
- 첫 상장, 상장폐지, 액면분할, 배당, 합병을 별도 기업행위 테이블로 기록.
- 재계산을 위해 게임 시작 시 시장 데이터 버전과 이벤트 버전을 고정한다.
- 2026년 10월 현재 확인되는 사후 수정 실거래 정보와 당시 공개 가능했던 정보의 차이를 추적한다. 공개 당시 정보를 재구성하지 못하면 **역사적 완벽 재현이 아닌 게임용 근사**임을 표시.
- 상업적 사용/시세 재전송 허용 여부를 자산군별로 기록하고 미해결 시 공개 제품에 포함하지 않는다.

### 8.3 역사 고증 수준
- **L1(프로토타입)**: 분기 가격·단순 수수료·고정 이벤트. 명확히 '게임용 단순화'로 표시.
- **L2(정식 MVP)**: 실제 체결가 기준·기업행위·환율·이자·거래일, 기본 거래 제한.
- **L3(확장)**: 시점별 제도/금리/거래세·대출·유동성·상세 부동산 모델.

## 9. 핵심 비즈니스·제품 지표

### North-star 제안
**완결된 20년 인생 시뮬레이션 수 / 주(WC20)**. 게임을 끝까지 경험해야 핵심 가치를 체감하므로 단순 세션 수보다 적합하다.

### MVP 퍼널 이벤트
`landing_view → game_start → onboarding_complete → turn_commit_1 → turn_commit_4 → turn_commit_20 → turn_commit_40 → turn_commit_80 → ending_view → new_run_start/share_card`

### 주요 KPI 가설 (출시 초기 목표가 아니라 실험 가설)
- 첫 턴 완료율 ≥ 80%
- 4턴(1년) 완료율 ≥ 60%
- 20턴 완료율 ≥ 35%
- 80턴 완료율 ≥ 15%
- 완주자 중 7일 내 재플레이 ≥ 25%
- 20턴 이전 주요 매매/인생 선택의 무효·오류율 < 1%
- 가격 누출/중복 정산/원장 불일치 0건

수치는 런칭 전 A/A·내부 테스트로 조정하며 제품 성공의 확정적 예측치로 취급하지 않는다.

### 분석 이벤트 공통 속성
`anonymous_player_id, run_id, seed_id, turn_index, game_quarter, mode, data_version, event_version, cash_bucket, net_worth_bucket, life_score_bucket, action_type, client_ts, server_ts`

### 실험 후보
- 턴당 AP 3 vs 4, 튜토리얼 텍스트 vs 카드형
- 첫 기억 카드 2장 vs 3장
- 다음 턴 전 '예상 생존비' 노출 vs 미노출
- 부동산 UX: 지역 리스트 vs 지도
- 엔딩 지표: 점수 우선 vs 스토리 우선

## 10. 요구 성능·보안·접근성
- 데스크톱/모바일 반응형 웹, 키보드 내비게이션, 주요 색상에만 의존하지 않는 수익/손실 표현.
- 터치로 거래 금액을 미리보기 한 뒤 별도 확인 클릭(오주문 방지).
- 정산 동작의 트랜잭션 원자성·멱등성 보장; 중복 제출 시 잔고 이중 반영 금지.
- 서버 authoritative 상태; 클라이언트 자산금액/가격 조작을 신뢰하지 않는다.
- 무료 익명 플레이 가능; 로그인 시 여러 회차/리더보드 저장. 민감한 실제 재무정보 불필요.
- 공유 카드에는 사용자의 실제 투자정보/실명 대신 게임 정보만 포함.
- 목표 성능(초기): 일반 턴 정산 p95 < 1.0초, 핵심 화면 p75 LCP < 2.5초(테스트 조건 명시).

## 12. 검증 시나리오 / Acceptance Tests

1. **80턴 경계**: 2006-Q4 t=0 시작, 2026-Q3 t=79 커밋 후 엔딩, 81번째 커밋 불가.
2. **현금 보존**: 매수 체결 시 현금 차감액 = 거래금액 + 비용; 매도 시 반대로 적용.
3. **매매 시점**: BTC 2006년, ETH 2014년, KRX 금 2013년 매수 불가.
4. **미래 데이터 비공개**: 2008-Q1 플레이에서는 2008-Q4의 가격·기사·확정 이벤트 결과 조회 불가.
5. **상태 재현**: 동일 seed + 초기 상태 + action log + data_version => 모든 턴 결과 해시 동일.
6. **중복 요청**: 동일 idempotency_key 커밋 2회 요청 시 단 한 번만 거래/급여/생활비 반영.
7. **파산 완주**: 현금 부족·실직 이후에도 복구 또는 채무 관리 플로우로 진행 가능.
8. **가족 선택권**: 비혼·무자녀 경로에서도 엔딩과 상위 점수 달성 가능.
9. **초기 접근성**: 현금 100만 원으로 첫 턴 생존 가능한 합리적 행동 조합 존재.
10. **거래 히스토리**: 모든 원장 변화가 행동·이벤트·시장 변동으로 설명 가능.
11. **기업행위**: 분할·배당·상장폐지가 데이터 반영 전후 자산을 이중 계산하지 않음.
12. **랭킹 무결성**: 자유모드/서버 미검증 데이터는 공식 시즌 랭킹 등록 불가.
